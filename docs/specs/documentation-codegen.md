# Mermaid、文档增强与代码生成

状态：1.0-C 需求基线；原生渲染与生成器细节待验证。Markdown 基础能力见[基础规格](core-workspace-http.md)。

## 1. Documentation Workspace

文档是独立 Markdown 文件，支持源码/预览/分栏、GFM、标题大纲、跨文档导航、本地图片拖入和全文搜索。结构化 API 定义负责方法、地址、参数、鉴权及 Schema；Markdown 负责目的、流程、约束和业务说明。

文档引用稳定请求 ID；Core 解析后派生接口卡片、参数表、响应定义及选定公开示例，并允许跳转请求。引用语法属于草案，例如：

```markdown
请先阅读认证说明，再调用当前用户接口。

[打开当前用户请求](gorequest://request/users.me)

<!-- gorequest:request id="users.me" view="parameters,responses" -->
```

以上协议与指令需格式评审；不是已注册的系统链接。普通 Markdown 阅读器至少可读周围叙述，导出时由 Core 展开派生内容。引用只读取本地定义，不在渲染时执行请求。已保存响应示例必须经脱敏审阅，不能用“最近一次响应”自动发布。

检测无效相对链接、缺失附件、失效请求 ID、未找到 Schema 和不支持图表语法；诊断定位文档及行。搜索可覆盖名称、URL、Markdown、Schema、SDL/Proto，索引为本机可重建缓存。

## 2. Mermaid 的需求与实现边界

Mermaid 是文本图表语法；其官方工具生态并不意味着 MyGo Markdown 组件自动具备兼容能力。[Mermaid 官方介绍](https://mermaid.js.org/intro/)

已确定：支持离线、保留源码、主界面继续使用 MyGo Native UI，不依赖在线图表服务或嵌入 WebView。原对话建议优先 Flowchart 与 Sequence Diagram；这属于候选实施顺序，完整语法范围与渲染器尚未确定。

候选方案为独立 Diagram Renderer：解析受支持子集，生成布局模型，由 MyGo 原生绘图显示；或评估预装的离线静态渲染链路。后者必须显式安装/调用、可取消并满足许可证、跨平台与无主界面 WebView 约束，不能偷偷下载运行时。选择之前需验证中文、字体、连线、复杂布局、错误定位、资源限制及导出。

不支持的语法显示完整源码和明确原因，不生成错误图掩盖缺失。用户必须知道当前兼容版本及子集；“部分 Mermaid 兼容”不能宣传成全量。限制节点、边、递归、布局时间与输出尺寸，禁止脚本、外链自动抓取和危险链接。

## 3. 文档导出

导出 Markdown 文档集和静态 HTML：收集必要本地附件，展开接口引用，生成相对路径导航，附版本/项目快照摘要。HTML 是交付文件，不是 Desktop 主界面的实现方式。

离线导出不得依赖 CDN 字体、远程 JS、远程图片或云服务。图表若当前不可渲染，保留源码并附兼容警告；HTML 对内容进行转义，外链用户主动打开。导出预览列明缺失引用、敏感信息和目标冲突；不能覆盖用户手工编辑的文档。

验收：两名开发者从 Git 克隆同一文档、图片、请求引用和受支持 Mermaid 示例，断网可一致阅读；修改一个请求后派生参数表更新，无需手改第二份表；缺失引用可定位，静态导出无在线依赖。

## 4. Request Snippet

把单个请求生成调用示例，优先 cURL、Go、Python、JavaScript/TypeScript。覆盖路径/Query 编码、重复 Header、JSON、Form、multipart 文件上传、鉴权、超时及错误处理；不支持的协议或选项明确提示，不输出表面可运行但语义错误的代码。

生成的是定义与环境的可审阅快照，默认 Secret 使用环境变量/配置占位。不能把当前 OAuth Token、密码、Cookie、私钥或本机绝对路径硬编码进去。生产目标和危险方法需清晰可见，复制动作不自动执行代码。

每个语言模板声明运行时/依赖版本与不支持项。Go 优先标准库，其他语言采用明确依赖；精确语言版本和 HTTP 库在实现前定稿。Secret 的读取和必要配置必须在示例中易理解，不能为简化示例静默跳过 TLS。

## 5. SDK Generator

与 Snippet 分开：从 OpenAPI/Proto 生成完整客户端、模型、鉴权入口、错误处理和调用示例。固定输入摘要、模板/工具版本、参数和输出清单；相同输入产生稳定输出，避免无关时间戳与随机排序。

OpenAPI 类型映射覆盖 nullable、组合类型、枚举、可选字段和错误响应；无法准确表示时生成明确报告。gRPC 优先标准 Protobuf 工具链，不自行重做协议生成；外部 protoc/plugin 必须用户显式配置并固定版本，不能执行仓库给出的未知程序。

生成到独立目录，先预览文件差异；已有文件冲突时停止或选择新目录，不覆盖用户代码、不自动删除旧输出。清理过期生成文件须依据上次清单并明确确认，手工文件永久保护。临时代码留在本机或 Git 忽略目录；用户有意交付的 SDK 是另一项显式导出。

离线能力以所选工具链已安装且本地依赖齐备为前提；缺工具时给出诊断，不自动联网安装。Core 接口允许不同生成器，但首版不开放任意远程模板脚本。

验收：由带 Query、JSON Body 和 Bearer 引用的请求生成 Go/Python/TypeScript，绑定环境凭据后对本地服务发出语义等价请求；multipart/编码边界有用例；重复生成无无关差异，冲突不覆盖；所有结果不包含真实 Secret。
