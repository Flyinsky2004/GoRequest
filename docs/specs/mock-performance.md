# Mock Server 与网络性能分析

状态：1.0-C 需求；基础 HTTP 计时可提前预埋。具体字段与统计口径为设计草案。

## 1. Mock Server 目标与输入

从 HTTP 请求、经脱敏保存的响应示例或 OpenAPI Schema 建立本地 Mock，在后端未就绪时供开发和回归测试使用。先覆盖确定性无状态 HTTP 规则；有状态业务模拟、GraphQL/gRPC Mock 后续评估。

规则定义放 `.gorequest/mocks/*.mock.yaml`；共享的是规则和公开示例，不是访问日志或捕获的凭据。Schema 生成的示例需满足约束；不能生成时给出具体限制并要求明确示例，不声称任意 Schema 都能合成有效数据。

## 2. 匹配与响应

- 匹配 Method、路径模板、路径参数、Query、Header、Body 文本/JSON 条件，可选择成功和 400/401/500 等错误场景。
- 规则使用显式优先级与稳定次序；同优先级重叠条件报告歧义，不能依赖文件系统顺序。精确匹配/模板/条件的优先关系需格式评审。
- 响应包含 Status、Headers、Body、固定/范围延迟；模板只读路径参数、显式变量和固定种子随机值，不执行任意代码。
- 未匹配默认返回清晰 404 和规则诊断；禁止静默代理到公网。
- CORS 可显式配置，不默认允许所有来源携带凭据。模板回显的用户输入按响应媒体类型编码。
- 延迟、Body、日志、连接数和请求体都有上限；取消应中止等待和响应写入。

## 3. 启动、日志与测试联动

```bash
# 未来 CLI 接口示例
gorequest mock start --project . --host 127.0.0.1 --port 4010
```

默认仅监听 `127.0.0.1`；用户明确选择才可监听局域网，UI 和 CLI 均提示实际地址。打开项目不自动监听；端口冲突不杀其他进程，也不悄悄换端口使测试打到错误服务。

测试套件可声明受控 Mock 生命周期：校验规则 → 启动 → 就绪检查 → 将实际端点注入本次运行变量 → 执行 → 无论成功/失败/取消均关闭。自动分配端口作为可选策略，只通过运行上下文传递，不回写共享环境。独立启动的 Mock 在 Ctrl+C 时停止接收并有界清理连接。

访问记录展示时间、匹配规则、脱敏请求与响应；保存在本机，支持清除与保留上限。切换场景需记录运行快照；测试开始后不让 GUI 临时操作悄悄改变本次套件规则。

验收：从 HTTP 响应 Schema 生成有效示例，成功/失败场景可切换；同规则与种子产生相同结果；默认监听不可从非回环接口访问；CLI 和测试自动清理后无残留进程/端口，日志没有 Secret。

## 4. HTTP 单请求时间线

计划使用 Go `net/http/httptrace` 采集 DNS、连接、TLS、请求写入和首字节等事件，结合 Body 读取与重定向事件建立时间线。哪些阶段实际可观测取决于连接、协议、代理与适配器，不能用不存在的事件编造精确耗时。[Go httptrace 官方文档](https://pkg.go.dev/net/http/httptrace)

草案口径如下；全部使用单调时钟计算持续时间，挂钟仅用于展示时间点：

| 指标 | 起止口径/边界 |
| --- | --- |
| DNS | 每次 DNSStart → DNSDone；复用或缓存无事件时显示未发生/不可观测 |
| TCP | 每个 ConnectStart → ConnectDone，保留并发拨号尝试和胜出连接，不简单相加 |
| TLS | TLSHandshakeStart → Done；错误单独标记 |
| 连接等待 | GetConn → GotConn，含连接池等待，可能覆盖 DNS/TCP/TLS，不可重复相加 |
| 请求写入 | 获得连接到 WroteRequest 的可观测区间，标注包含的编码/调度等待限制 |
| TTFB | 本跳请求开始到 GotFirstResponseByte；另列写完请求到首字节的等待 |
| 下载 | 首字节到 Body EOF；中断/超限明确不是完整下载 |
| 本跳耗时 | 本跳开始到 Body EOF/失败/取消 |
| 请求总耗时 | 第一跳开始到最后一跳结束，含重定向与必要连接等待 |

每跳显示 URL（脱敏）、状态、实际 HTTP 协议、远端地址、连接是否复用。复用连接的 DNS/TCP/TLS 显示“不发生（连接复用）”，未知显示“不可观测”，都不是 0 ms 样本。HTTP/2 多路复用、Happy Eyeballs 并发连接和早到响应可能产生重叠，UI 使用区间，不能画成必然可相加的流水线。

代理场景标识直连、代理连接与可观测 CONNECT/TLS；无法分解代理 DNS 或隧道内部时间时明确缺失。TTFB 包含网络和服务端等待，不能直接标为后端处理时长。无 Body、HEAD、流响应和取消分别说明结束边界。

## 5. 重复采样与分位数

支持次数、并发上限、间隔、预热、总体截止时间、种子及连接复用策略；这些配置随报告保存。普通诊断先采用有限次数的低并发采样，不宣称完整负载测试或压测容量结论。

设计草案使用 nearest-rank：成功且完整的延迟样本排序后，`Pq = x[ceil(q × n)]`（1-based，q 为 0.50/0.90/0.95/0.99）。同时输出 n、平均值、最小/最大、P50/P90/P95/P99、成功率、失败/超时/取消数、预热数和统计方法。小样本明确提示分位数分辨率限制。

成功请求的延迟统计不能掩盖失败：失败耗时另列，超时不填成 0 或丢掉后声称性能优秀。阶段样本仅统计该阶段真实发生且完整的记录，各阶段有独立样本数。阈值门禁同时声明分位数、最小有效样本数、最大失败率；样本不足为不可判定/门禁失败，具体结果枚举待定。

历史比较使用相同请求/环境/Core/种子/采样与连接策略，显示不可比差异；不得把本机网络变化当后端性能回归的确定证据。输出 JSON/CSV 和后续可视化 HTML，均为不入 Git 的运行报告。固定脱敏摘要可由用户有意另存作为基线，不能自动纳入项目。

验收：覆盖直连、代理、重定向、首次连接、连接复用、HTTP/2、失败与取消；已知样本 `[100, 200, 300, 400, 500] ms` 的 P50 为 300、P95/P99 为 500，复用阶段不参与 DNS 等统计。GUI 与 CLI 对同一采样数据的聚合一致。
