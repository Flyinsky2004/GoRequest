# 桌面测试自动化、集合 Runner 与报告

状态：1.0-A 需求基线；Runner、断言、提取、报告字段为设计草案，尚未实现。GoRequest 以 MyGo 原生桌面应用交付，**不提供独立产品 CLI**，也不把“在无桌面 CI 中运行用户项目”作为产品需求。

## 1. Collection Runner 与 Test Suite（桌面内）

Collection 用于组织请求，桌面内的 Runner 可按显式顺序运行集合或文件夹；Test Suite 用于业务场景，可跨集合选择请求，声明依赖和数据传递。所有执行都经过共享纯 Go Core，界面不复制执行引擎、断言或变量解析逻辑。不得把显示排序或磁盘遍历顺序隐式当作测试依赖。

单请求支持断言；套件叠加步骤断言、变量和重试策略。执行前一次性校验 ID、依赖环、环境、必需密钥、数据集、Schema 与目标策略；无法建立有效计划时不发送任何请求。

前置/后置能力先采用声明式动作：设置变量、生成动态数据、准备或清理显式测试资源。任意 JavaScript/Go/shell 脚本不在初期范围。未来脚本需独立安全评审与授权机制。

## 2. 数据驱动与状态隔离

- CSV 表头映射字段，JSON 使用对象数组；明确 UTF-8、空值、缺列、数字/布尔等类型转换，转换失败定位到行与字段。
- 每行创建独立迭代上下文、Cookie Jar 和步骤输出，失败不能污染下一行。大数据集采用受限流式读取，限制行数及资源。
- 独立步骤可限制并发；有依赖的步骤等待所有必需上游成功。并发分支不可共同写普通变量；下游通过 `steps.<id>.<output>` 读取显式输出。
- 动态 UUID、时间、随机字符串只在指定作用域生成一次并缓存，不能每次模板引用都变化。固定种子和冻结时钟用于可重复测试，但业务秘密仍来自凭据后端。
- 运行变量不回写共享环境，敏感属性沿提取、模板和报告传播。

## 3. 断言与提取

| 类别 | 要求 |
| --- | --- |
| HTTP | 状态码、Header、Cookie、Body 文本/JSONPath、响应大小与耗时 |
| Schema | 根据指定 JSON Schema/OpenAPI Operation 校验请求或实际响应，输出实例路径、期望与实际 |
| 数据比较 | exists/equals/contains/类型/范围/正则；明确空值与缺字段不同 |
| GraphQL | 同时区分传输、`data` 与 `errors`，允许声明预期的部分错误 |
| 流协议 | WebSocket/gRPC/Subscription 在时限内等待满足条件的消息，校验序列、数量、状态与关闭 |
| 统计 | 重复采样的 P95 等阈值单独标识样本范围，不混入单次延迟断言 |

JSONPath 和正则方言、类型强制规则、耗时边界属于待定格式契约，必须在文档及 Core 中统一。提取支持 JSONPath、Header，后续扩展 Cookie/文本；缺失必需输出导致步骤失败，不发布半成品输出。默认仅当传输与步骤断言成功后提交提取值；失败时原始诊断需脱敏。

## 4. 失败、重试与取消

`onFailure: stop` 停止启动新步骤；`continue` 运行仍可执行的独立分支，依赖失败的后继标为 skipped。套件取消标为 canceled；其余未启动步骤不伪装成通过。

自动重试默认关闭。显式策略可限定网络错误、状态码或断言类型，配置最大次数、退避、抖动和总 Deadline。非幂等请求需要明确允许；每次尝试保留事件和结果，既展示最终判定也展示重试次数，不能靠重试抹去不稳定性。取消和配置错误不重试。

结果分类（在桌面内展示，不涉及命令行退出码）：网络超时、TLS/连接失败、服务拒绝、协议错误及断言失败属于**运行失败**；项目定义错误/缺密钥/格式不兼容属于**配置错误**；执行器崩溃、无法写最终报告等本地内部故障属于**内部故障**；用户取消单列。正常响应但未声明状态断言时，HTTP 4xx/5xx 作为协议事实展示，是否通过由测试规则决定；不得隐式把所有错误状态当引擎故障。

## 5. 统一结果与报告

结果模型至少包含项目/格式/Core 版本、项目快照摘要、run ID、环境名称、种子、开始/结束时间、总时长、数据行、步骤/尝试、协议事实、断言、提取元信息、Trace、失败分类和跳过/取消原因。

- JSON 为机器消费的完整结构；JUnit XML 提供测试用例与失败详情（可被外部 CI 工具消费）；静态 HTML 在后续阶段展示，性能采样另提供 CSV。
- 结果与报告在桌面内展示，并可导出到本机运行目录；诊断信息与结果同样脱敏。
- 退出、取消和报告写入遵循最终化流程：关闭连接、停止临时 Mock、写入完整或明确标记不完整的报告。磁盘失败要如实反馈错误。
- Secret、Authorization、Cookie、私钥、敏感提取值及包含它们的正文不能进入日志/报告。失败断言的“实际值”也必须脱敏。
- 报告默认写本机运行目录；写入仓库内显式输出仅在目标已忽略时允许。报告不作为共享项目事实来源。

## 6. 桌面运行与自动化入口

- 用户在桌面内选择请求/集合/套件运行，查看实时进度、逐步结果与最终报告；结果可导出为 JSON/JUnit 到本机目录。
- 程序化自动化通过桌面应用或测试工具调用共享 Core 完成；**产品不提供无界面命令行入口**（用户于 2026-11-05 决策取消独立 CLI，见 [决策 ADR-009](../decisions.md)）。
- Secret 通过桌面本地凭据后端或环境变量注入；共享项目文件只保存 `{{secret.name}}` 引用。

## 7. 仓库自身的构建与测试 CI（保留）

本仓库对自身 Go 代码运行 `go build ./...`、`go test ./...`、`go vet ./...` 作为工程质量门禁。这属于仓库开发流程，**不同于**“用产品在无桌面 CI 中运行用户项目”——后者已随 CLI 取消而不属于产品需求。

## 8. 验收

完成登录 → 提取敏感 Token → 查询用户 → 更新资料 → 验证设置的业务套件；用两行数据确认隔离，在桌面内得到一致判定。再验证故意断言失败、连接失败、配置错误、超时、取消、报告写失败和空筛选的结果分类与报告内容。JUnit/JSON 不出现测试注入的可识别秘密值。
