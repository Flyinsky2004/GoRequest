# U16 渲染式文档光标与斜杠输入：实现报告

日期：2026-11-08。分支：`cc/U16-doc-input-slash`。实际目录：`/private/tmp/gorequest-u16-u17-20261108/doc-input-slash`。共同基线：`238e426`（U16–U17 登记提交）。代码交付提交：`a82f686`。

## 1. 交付范围

本轮修复渲染式文档画布的两个真实链路问题，并补齐回归测试：

- 点击块激活后没有可见光标；
- 回车产生新行后，行首输入 `/` 不弹出 Markdown 组件菜单。

同时修正点击多行块时光标落错行的问题。未改 `doc_table*.go`、`internal/doctable`、`tab.go`、`app.go` 或任何 U12 壳层文件；表格命令继续走既有 `renderDocTable` 接口，因此不需要 `U16-integration.patch`。

## 2. 根因与修复

### 2.1 光标不可见：Key 在 editor.View 构建之后才应用

`editor.View` 在构建开始时读取 `e.Focused()`，据此决定是否绘制光标；默认 `CursorBar` 只在 `ed.focused` 为真时绘制。原实现是：

```go
view := editor.View(c, be.ed).FillWidth().Key("doc-canvas-editor")
...
view.Focus()
```

`Key` 在 `editor.View` 返回之后才把节点改键为 `"doc-canvas-editor"`，而 `Focus()` 设置的是改键后的 id；编辑器构建时读到的是改键前的按位置 id。两者永远不一致，`ed.focused` 每帧都是 false，光标因此从未绘制。输入法仍能工作，是因为输入处理器挂在节点上，与这个焦点读取无关——这也解释了“能打字但看不到光标”。

修复：在编辑器外增加带 key 的宿主元素，让编辑器自身的按位置 id 在帧间稳定，`Focus` 与 `Focused` 指向同一节点：

```go
host := ui.Column(c).FillWidth().Key("doc-canvas-editor-host")
host.Children(func() {
    view := editor.View(c, be.ed).FillWidth()
    if be.focusPending {
        view.Focus()
        be.focusPending = false
        c.Invalidate()
    }
    view.Label("doc-canvas-editor")
})
```

`Focus()` 本身不请求下一帧；补 `c.Invalidate()`，使“只点击、不输入”也能在下一帧画出真实光标。没有绘制任何替身光标。

### 2.2 点击多行块落错行

`activateDocBlock` 用 `clickY / docBlockLineHeight(...)` 求行号，但 `docBlockLineHeight` 返回的是行高倍数（约 1.5），不是像素。点击 8px 处会算出第 5 行，再被夹到最后一行。新增 `docBlockLinePixels`（字号 × 行高倍数）作为除数，点击落在实际行上。

### 2.3 新行 `/` 不弹菜单：按整块判断且被空查询吞掉

原 `SlashQuery` 要求整个块是单行；回车在段落内产生第二行（软换行）后，块文本变成多行，判断直接失败。另外 `slashDismissed` 的零值 `""` 与空查询（只输入 `/`）相同，`refreshDocSlash` 第一帧就把空查询当成“已关闭”，所以单输入 `/` 永远不弹菜单。

修复：

- `docedit.SlashQueryLine`：判断单条逻辑行；`SlashQueryAt(text, caret)` 取光标所在逻辑行，并要求光标不在起始 `/` 之前。路径、URL、代码块、非行首 `/` 仍不触发。
- `refreshDocSlash` 改用 `SlashQueryAt`。
- 新增 `slashDismissedSet`，把“空查询”和“没有关闭过”分开；Escape/头部按钮关闭时记录，查询变化或重新激活块时清除。
- `applyDocSlashText` 只替换光标所在逻辑行，块内其余行逐字节保留；选择区间按行偏移换算，选中后可直接替换查询文字。
- 菜单容器 `KeepFocus()`，鼠标点选菜单项不会把焦点从编辑器抢走。

## 5. 限制

- 未启动真实桌面窗口，以上是 `ui.Tester` headless 绘制与输入验证，不构成实机验收；未提供实机截图。
- 真实 macOS 中文输入法组合期间按 Enter 的行为未实机验证。headless 只能模拟 composition 文本；实现依赖平台在组合期间不把确认键送到应用，未额外读取编辑器内部 marked 状态。
- 斜杠菜单仍在画布滚动内容内、活动块下方：不会覆盖光标，且被滚动容器裁剪在窗口内；窗口很矮时可能需要滚动才能看全，未做浮层自动翻转/自动滚动。
- 引用块行（`> /h2`）不会触发菜单；列表标记（`- /h2`）会触发。正文、路径、URL、代码块、非行首 `/` 均不误触。
- 表格命令插入表格源码后仍停在块编辑器；按 Escape 退出后由 `renderDocTable` 渲染。这是与现有画布编辑模型一致的行为。
- 光标闪烁由编辑器自身驱动；测试冻结时钟，只断言焦点帧的光标绘制，不断言闪烁动画。
