## 1. 实际完成范围与归属文件清单

### 1.1 纯 Go Core 层（`internal/core/`，零 GUI/MyGo 依赖）

1. **阶段超时、重定向策略、目标策略逐跳挂接与传输/解压大小分离（`internal/core/plan.go` 仅 `Execute`/transport 区、`internal/core/network.go`）**：
   - `StageTimeouts`：支持独立配置 `DialTimeout`（默认 `10s`）、`TLSHandshakeTimeout`（默认 `10s`）、`ResponseHeaderTimeout`（TTFB，默认 `30s`）与 `TotalTimeout`，所有阶段均绑定 `context.Context` 并在下载中途取消时立即关闭 `resp.Body` 释放底层 socket。
   - `RedirectPolicy`：支持 `follow`、`none`（直接返回第一跳 3xx）、`same_origin`（跨源/跨端口/协议变化即拦截）及 `MaxHops`（默认 `10`）。
   - **对接 B05 目标策略与敏感凭据剥离**：初始跳（Hop 0）调用 `EvaluateTarget`，重定向每一跳（Hop $1 \dots N$）在 `CheckRedirect` 中调用 `EvaluateRedirectHop` 重新校验目标主机黑白名单与生产策略；跨源或 `https` → `http` 降级跳转时自动剥离 `Authorization`、`Proxy-Authorization`、`Cookie`、当前 `AuthScheme` 声明的自定义 `apikey` 请求头以及 `Redactor` 中登记的敏感头，并生成逐跳审计记录 `[]RedirectHop`。
   - **区分网络传输字节与解压后 Body 大小**：Transport 层启用受控流式读取，`wireCountingReader` 精确计量底层传输字节 `TransferSize`，外层支持 `gzip` / `x-gzip` / `deflate`（自动识别 zlib 封装与原始 raw flate）流式解压并按 `MaxResponseBytes`（默认 `32 MiB`）有界截断，分别记录 `TransferSize`、`BodySize`、`ContentEncoding` 与 `Decompressed`。
   - **阶段观测追踪（`NetworkTrace`）**：基于 `httptrace.ClientTrace` 记录 DNS、TCP Connect、TLS Handshake、Request Write、TTFB 与 Download 耗时，未触发阶段（如连接复用时的 DNS/Connect/TLS）保持 `Observed=false`，绝不伪造 `0ms`。
2. **HTTP / SOCKS5 代理与 NoProxy 规则（`internal/core/network_proxy.go`）**：
   - 支持 `system`、`none`（强制直连）、`http`（HTTP/HTTPS 代理 + Basic `Proxy-Authorization`）、`socks5`（纯 Go RFC 1928 + RFC 1929 用户名/密码认证拨号器，支持 `socks5://` 与 `socks5h://`）。
   - `ShouldBypassProxy` 支持 `*`、精确域名、`.domain` / `*.domain` 子域后缀、`host:port` 与 IP CIDR 匹配；代理凭据仅从本机内存或 `SecretProvider` 读取并自动向 `Redactor.RegisterBasicPair` 登记。
3. **系统/自定义 CA、mTLS 本机私钥边界与错误分类诊断（`internal/core/network_tls.go`）**：
   - 默认强制开启 TLS 证书与主机名校验（最低 `TLS 1.2`）；当 `MergedTargetPolicy.EnforceTLSVerify == true`（默认）时拒绝 `InsecureSkipVerify`。
   - 支持系统根证书池（`UseSystemCA`）与 `CustomCARef`（`local:<slot>` 或项目内相对 PEM，上限 `4 MiB`）。
   - **mTLS 私钥本机强制边界**：`ClientKeyRef` 强制要求 `local:<slot>` 本机映射槽位，引用共享项目路径（如 `certs/client.key`）在发网前直接以 `*ConfigError` 拦截；私钥加载后立即向 `Redactor` 登记。
   - `classifyTransportError` 将未知/自签 CA、主机名不匹配、过期证书、mTLS 客户端证书被拒、代理握手/认证失败、TTFB 超时、拨号超时分类包装为可定位的 `*RunError` 并经 `Redactor.RedactError` 脱敏。
4. **按项目/会话隔离 Cookie Jar（`internal/core/cookies.go`）**：
   - 无全局 Cookie 状态：`NewCookieJar(scopeID)` 按项目隔离，`CloneForSession` 按单次运行/数据行深拷贝隔离，子会话修改不回写父罐。
   - 实现 RFC 6265 域名匹配（区分 `HostOnly` 与子域匹配，拦截跨站域与单标签公共后缀）、最长路径优先排序、`Secure` 传输保护、`Max-Age`/`Expires` 过期淘汰、请求头安全合并 `MergeHeadersWithCookies`、响应 `ParseResponseCookies` 及 `Redactor` 自动脱敏登记。
5. **保序有界 JSON 树与二进制载荷检测（`internal/core/network_json.go`、`internal/core/network.go`）**：
   - `ParseJSONTree` 使用 `json.Decoder` Token 流保留服务端原始对象键序与数字字面量，受 `MaxJSONTreeBytes`（`2 MiB`）与 `MaxJSONTreeNodes`（`5000` 节点）约束；`FlattenJSONTree` 支持折叠态、受限搜索（上限 `10000` 处）及匹配节点祖先链自动展开。
   - `InspectPayload` 与 `FormatBinaryPreview` 识别二进制响应、清洗 `Content-Disposition` 推荐文件名（防 `../` 路径穿越）并生成前 512 字节十六进制预览与 SHA-256 摘要。
