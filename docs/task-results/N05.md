## 2. 实现结果

### 2.1 纯 Go 生成器 `internal/sdkgen`

分层：`SpecSnapshot → Parse/Validate → SupportedOperations → GeneratedFiles → Preview → Apply`。

- `sdkgen.go`：`Options`/`Result`/`File`/`Operation`/`UnsupportedOperation`/`Diagnostic`，固定 `GeneratorVersion=sdkgen-go/1`、`TemplateVersion=1`，默认上限 500 文件 / 32 MiB，错误哨兵（unsupported/unsafe target/conflict/invalid manifest/limit）。
- `spec.go`：只接受 OpenAPI `3.1.x`/`3.2.x` JSON；标准 HTTP method + 3.2 `query`；本地 `$ref` 解析；primitive path/query/header 参数与 primitive 数组；`application/json`/无 Body；operation 级不支持诊断（multipart/binary/多媒体 Body、远程 ref、callbacks、webhooks、3.2 streaming、AND security、cookie 参数、deepObject、object schema、受管理 header、additionalOperations）。
- `names.go`：operationId 缺失时按 method+path 稳定派生；Go 标识符规范化、关键字/数字开头/重名/大小写冲突；排序不依赖 map。
- `generate.go`：生成 `go.mod`、`client.go`、`operations.go`（每 operation 的 Input/Validate/方法）、最小 `README.md`、`.gorequest-sdk-manifest.json`；所有 Go 源经 `go/format`；不嵌入示例/Secret/服务器 URL；README 标题对疑似凭据做保守回退。
- `apply.go`：项目外绝对目录校验（拒绝文件系统根、项目根/`.gorequest` 内、symlink 目标）；manifest 版本/路径/大小校验；Preview 列出 create/update/unchanged/delete-stale/conflicts/stale；Apply 重新校验基线、手工文件/被改生成文件/恶意 manifest/symlink 阻断、写失败回滚、manifest 最后提交；文件数/字节上限。

### 2.2 桌面原生模态 `internal/desktop/sdk*.go`

- `sdk_state.go`：per-window `SDKState`（weak + cleanup）；`OpenSDKModal` 只设默认值不生成；`RefreshSDKPreview` 在 UI 线程导出严格 JSON 快照，后台跑 `sdkgen.Preview`，`win.Update` 回所属窗口，generation/关闭防护；`ApplySDK` 只在无冲突时写盘；`PickSDKTargetDir` 原生目录选择；`SDKView` 供 headless 测试。
- `sdk_ui.go`：项目菜单入口、模态（3.1/3.2 切换、包名/模块名、项目外目录、三个默认关闭的显式选项、预览/冲突/不支持/stale/文件动作/operations/manifest 版本、成功/失败反馈）；打开模态不发网、不运行生成器。
- `sdk_i18n.go`：中英词条。

## 3. 数据与兼容范围

- 输入：`core.ExportOpenAPI` 的 JSON 快照，固定目标版本 3.1.2 或 3.2.1，`Strict=true`、`AllowLossy=false`、`IncludeExamples=false`。
- 支持：标准 HTTP method（get/put/post/delete/options/head/patch/trace）+ 3.2 `query`；primitive path/query/header 参数；query 数组 `form` explode true/false、`spaceDelimited`、`pipeDelimited`；path/header 数组 simple 逗号；`application/json` Body（`json.RawMessage`）；无 Body。
- 不支持并默认阻断：multipart/binary/urlencoded/多媒体 Body、远程 ref、callbacks、webhooks、3.2 streaming、AND security、cookie 参数、deepObject、object/union schema、受管理 header、additionalOperations。显式“只生成支持子集”时跳过并在 README/预览列出。
- 生成客户端：仅标准库；`NewClient(baseURL, opts...)`；`Client.Auth func(*http.Request) error`；默认 30s timeout；响应读上限 8 MiB；非 2xx 返回 `*APIError`（真实状态/头/有界正文）；`context` 取消传播；body/连接关闭；path 分段 `url.PathEscape`；base path 拼接；query 合并不双重编码；header 换行注入拒绝。
- manifest：`generatorVersion`/`templateVersion`/`specDigest`/`packageName`/`modulePath`/`files[{path,digest,kind}]`；不记录时间/run ID；不列自身。
- 兼容：生成模块 `go.mod` 声明 `go 1.21`，只用标准库；不修改仓库依赖。

## 7. 未完成与限制

- 首阶段只做 Go HTTP SDK；Python/JS/TS SDK、Proto、完整 Schema 类型生成、gRPC/WS 不在本卡。
- 响应只保留 `Raw JSON/bytes`，不生成每状态/每 Schema 的模型类型；不伪称覆盖所有 OpenAPI 类型。
- 不支持项默认阻断；只有显式勾选“只生成支持子集”才跳过并列出。webhooks 作为不支持项阻断（不是 operation，但会阻止默认生成）。
- 未做真实窗口/三平台人工验收；headless `ui.Tester` 不等于系统输入法、窗口、真实文件选择器或平台验收。
- 未调用真实 Secret/生产服务；生成模块测试只用 loopback 和 fake 值。
- 生成代码不自动执行；产品不自动运行新代码。
- `go test ./...` 的四项既有失败未修（N01 负责）；本卡只记录。
