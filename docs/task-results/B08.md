- **cURL 纯 Go 词法与参数解析契约**：覆盖支持参数、不支持参数的显式诊断报告（`LossItem`）、反引号与 `$()` 命令替换拦截、敏感凭据槽位自动转 `{{secret.<slot>}}` 与本机 `@path` 自动转 `local:<slot>`。
- **Postman Collection / Environment 明确版本矩阵**：支持 Collection `v2.1.0` 与 `v2.0.0` 及 Environment `postman_variable_scope: environment`；显式拒绝 Legacy `v1.0`（`postman-v1-unsupported`）；脚本 `event`（`prerequest`/`test`）永不执行并逐项记入损失报告；`oauth2`/`awsv4`/`digest` 等高级鉴权（归属 `A04`）不静默丢弃而是记入 `Losses`。
- **OpenAPI / Swagger 分流诊断边界（`A03`）**：检测到 `openapi: 3.x` 或 `swagger: "2.0"` JSON/YAML 时，返回 `CanApply: false` 与 `openapi-routed-to-a03` 诊断，明确指引至 `A03` 模块，绝不伪造半成品转换。
- **原生便携包（`.gorequest-bundle.zip`）与归档安全边界**：支持单请求（`request`）、文件夹子树（`folder`）与完整项目（`project`）三级作用域及所引用的公开依赖（`auth/*.auth.yaml`、`docs/*.md`、`assets/*`、项目内相对路径附件）；强制排除密钥、Cookie、历史、`local-files.json`、`config.json` 与宿主机绝对路径；内置条目数、单文件体积、总解压体积、压缩比上限与路径穿越/符号链接拦截。

### 1.2 Core 基础互操作引擎（`internal/core/interop_*.go`）

1. **统一预览、冲突策略与事务应用模型（`internal/core/interop_types.go`）**：
   - 定义 `InteropFormat`（`curl` / `postman-collection` / `postman-environment` / `portable-bundle` / `openapi`）、`ConflictPolicy`（`fail` / `rename` / `overwrite` / `skip`）、`LossItem`、`IDMapping`、`VariableSourceNote`、`ImportPreview`、`ImportPlan` 与 `ImportReceipt`。
   - 提供 `DetectInteropFormat` 与 `StageAutoImport`：自动识别输入格式并对 OpenAPI 3.x / Swagger 2.0 给出 `ErrOpenAPIRoutedToA03` 阻断式预览。
   - 完整复用 B01 `Project.StageChangeSet`、`Preview`、`Apply` 与 `Rollback`：任何导入先生成包含新增/覆盖/跳过路径、ID 重映射、变量来源、脱敏秘密槽位和损失项的 `ImportPlan`，用户确认后才通过 `Apply()` 原子写盘，且支持 `ImportReceipt.Rollback()` 一键回滚并调用 `ReloadProjectInMemory` 刷新内存模型。
2. **纯 Go 零 Shell cURL 解析器与脱敏导出器（`internal/core/interop_curl.go`）**：
   - `TokenizeCURL` 与 `ParseCURLCommand`：纯 Go 状态机处理单引号、双引号、ANSI-C `$'...'` 转义与 `\` 续行；主动拦截未引号包裹或双引号内的 `$(...)` 与反引号命令替换（`curl-shell-expansion-blocked`），**绝不调用 `os/exec` 或任何外部 shell**。
   - 支持 `-X`/`--request`、`--url`、`-G`/`--get`、`-I`/`--head`、`-H`/`--header`、`-u`/`--user`（Basic）、`-b`/`--cookie`、`-A`/`--user-agent`、`-e`/`--referer`、`-d`/`--data`/`--data-raw`/`--data-urlencode`/`--data-binary`/`--json`、`-F`/`--form`（multipart 字段与 `@file` 附件）；自动识别敏感头/槽位并转化为 `{{secret.<slot>}}` + `Redactor` 注册；将外部 `@/abs/path` 转为 `local:<slot>` 占位而不复制宿主私密文件；对 `-k`/`-L`/`-x`/`--cert` 等运行期网络标志生成 `LossItem` 报告。
   - `ExportRedactedCURL`：结合 B03 `PrepareRequestBody` 与 B05 `Redactor` 生成可直接分享的脱敏 cURL 命令（自动掩码 `Authorization`、`Cookie`、自定义 `apikey` 槽位及已注册秘密，本机文件槽位输出 `@<local:slot>` 占位符）。
3. **Postman Collection (v2.1.0 / v2.0.0) 与 Environment 导入导出（`internal/core/interop_postman.go`）**：
   - `StagePostmanCollectionImport` 与 `StagePostmanEnvironmentImport`：校验 Schema 版本矩阵（拒绝 v1.0），递归转换嵌套文件夹、请求、Query、Header、Body（`raw`/`urlencoded`/`formdata`/`file`）与 Auth（`bearer`/`basic`/`apikey`/`noauth`）；自动提取 `secret` 类型变量与敏感鉴权值至 `Environment.Secrets` 及 `{{secret.<slot>}}`；不执行任何 `prerequest`/`test` 脚本并将脚本、保存的响应示例、不支持的高级鉴权全部列入 `Losses`。
   - `ExportPostmanCollection` 与 `ExportPostmanEnvironment`：导出标准 Postman v2.1.0 Collection 与 Environment JSON，秘密槽位仅导出 `{{secret.<name>}}` 模板占位符或空值 `type: "secret"`，绝不导出真实密钥。
4. **原生便携包（`.gorequest-bundle.zip`）导入导出与归档安全防护（`internal/core/interop_portable.go`）**：
   - `ExportPortableBundle` / `ExportPortableBundleToFile`：支持 `PortableScopeRequest`、`PortableScopeFolder`、`PortableScopeProject`；自动收集请求引用的 `.gorequest/auth/*.auth.yaml`、请求/集合级 `docs/*.md`、`assets/*` 以及项目内相对路径附件；写入带 SHA-256 校验和与脱敏审计的 `manifest.json`；严格排除 `.gorequest/local-files.json`、系统钥匙串秘密、Cookie、历史、设备配置与宿主机路径。
   - `StagePortableBundleImport` / `ImportPortableProjectToDir`：执行 ZIP 条目数（`<= 2048`）、单条目体积（`<= 16 MiB`）、总解压体积（`<= 64 MiB`）、压缩比（`<= 100:1`）、路径穿越（`..` / 绝对路径）、符号链接/设备节点逃逸与 SHA-256 完整性校验；支持 4 种冲突策略，其中 `ConflictRenameNewID` 自动分配新 ID 并重写所有请求内的 `auth.ref` 关联引用。
