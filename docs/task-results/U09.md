### URL 处理

`historyEndpoint` 用 `net/url` 解析，不做字符串截断：

| 输入 | 显示 |
| --- | --- |
| `https://api.test/v1/users?page=2#top` | `/v1/users?page=2#top` |
| `http://[::1]:8080/api/items?x=1` | `/api/items?x=1` |
| `https://api.test` | `/` |
| `https://api.test?x=1` | `/?x=1` |
| `https://api.test/a%2Fb?x=%20#f%20` | `/a%2Fb?x=%20#f%20` |
| `https://user:pw@api.test/x` | `/x`（userinfo 一并隐藏） |
| `/api/users?x=1#f`、`//api.test/x?y=1` | 相对引用保留原样；scheme-relative 去掉 authority |
| `mailto:user@example.com`、`not-a-url`、`http://[::1` | 解析失败/无 authority/opaque 时保守返回原串 |

路径用 `EscapedPath()` 保留转义，query 用 `RawQuery` 原样保留，fragment 用 `EscapedFragment()`；无路径根补 `/`。

## 完整 URL tooltip

`historyRow` 对整行设置 `.Tooltip(r.URL)`。无论开关状态、行内文本是否被截断，悬浮记录即可读到已脱敏的完整 URL；只读记录字段，不重新读取 secret。

## 行内动作区

- 旧实现：`ui.Button("i")` / `ui.Button("✕")` 绝对定位 `Right(26)` / `Right(2)`，默认按钮宽度互相重叠并压住状态/耗时。
- 新实现：行尾固定 52 DIP 动作槽（24 + 4 + 24），`Shrink(0)`，两个 24×24 紧凑按钮，间距 4 DIP；不重叠、不挤压彼此。
- 图标：详情用现有 `uikit.IconMore`（中性 `p.Muted`，hover `p.Text`）；删除用现有 `uikit.IconClose`，颜色 `t.Danger`。
- 状态：背景 `p.Hover` / `p.Press`（120ms `uikit.AnimHover`），键盘焦点用 `painter.FocusRing`（主题 focus），两个按钮都有 label 和 tooltip。
- 点击互斥：两个按钮是独立可点击 box；点击详情只打开详情，点击删除只删除当前记录，都不会触发父行 `restoreHistory`，也不会互相误点。行本身点击仍恢复完整 URL。
- 窄侧栏：动作槽 `Shrink(0)`，URL 用 `Grow(1)` 吸收/让出空间，布局不重叠。实测 220/260/380 DIP 下详情/删除按钮位置分别为 162–186/190–214、202–226/230–254、322–346/350–374，均无交叠。极窄 220 DIP 时 URL 文本会被压到 0 宽，此时仍可悬浮整行读取完整 URL；这是保留状态/耗时/动作槽的取舍。
