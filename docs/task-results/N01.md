## 2. 根因判定（fixture 错误 vs 生产 bug）

| 用例 | 判定 | 证据 |
| --- | --- | --- |
| `TestRunnerEditorDescribeAssertions` | **fixture 错误** | 测试输入为 6 项合法 + append 1 项非法 = 7 项，却断言 6 项并把第 6 项（合法 `schema`）当 invalid。`DescribeAssertions` 输入输出一对一，`parseSchemaExpectation` 对 `ref: schemas/login.yaml` 返回 `targetSchema`，对 `ref: ""` 返回错误。 |
| `TestRunnerEditorPatchSuiteExtract` | **生产 bug** | `runnerEditorPatchSuiteExtract` 删除整个 `extract` key/value 再追加新节点；实测 `# step comment stays` 是 `extract` **key 节点**的 `HeadComment`，随 key 一起被删，注释丢失。 |
| `TestMockEditorSuggestionsAreProjectUnique` | **fixture 错误** | `taken` 只含 `x-copy`/`x-copy-2`，不含来源规则 `x`，却期望 `x-copy-3`。真实复制调用 `newMockRuleEditorFor(dup=true)` 会把来源文件全部规则（含来源 ID）加入 taken，因此 `mockSuggestCopyID` 在 `x` 已占用时正确返回 `x-copy-3`。 |
| `TestEngine_PolicyBlockedAndMissingSecretPreflight` | **fixture 错误** | `makeTestProject` 生成 GET；Core 默认 `ActionConfirm` 只要求**变更方法**确认，安全读取 GET 允许。`EvaluateTarget` 中 `IsMutating = !IsSafeReadMethod(method)`，GET 为 false 不触发确认。 |
