## 1. 实际范围

### 1.1 保留并扩展既有能力

`internal/desktop/history.go` 原有按项目克隆隔离的元数据 JSONL、列表、清除、删除、恢复入口全部保留：

- `historyRecord` 仍是桌面侧使用的记录类型，旧字段名（`ts`、`method`、`url`、`env`、`status`、`durationMs`、`size`、`requestId`）不变；旧 JSONL 文件可直接加载。
- `historyStore` 仍提供 `load`/`append`/`remove`/`clear`，现有测试与调用不需要重写。
- `historyKey` 仍按“项目稳定 ID + 规范化本地根路径哈希”生成，不同克隆不共享历史。
- 点击历史行恢复请求、清除确认弹窗、按天分组等交互保留。

### 1.2 新增纯 Go 历史引擎

新增 `internal/localstate/history.go`（不依赖 MyGo/窗口/平台 UI；仅复用 `internal/core` 的 `Redactor`）：

- **记录模型**：`Record` 在旧元数据上增加 `proto`、`outcome`、`error`、`request`/`response` 快照。`outcome` 分为 `ok`（收到响应，含 4xx/5xx）、`error`、`canceled`、`timeout`。
- **HistoryInput 端口**：`localstate.HistoryInput` 是供桌面当前 HTTP `Plan`/`ExecResult`/error/canceled 以及未来 Runner 复用的输入结构。字段是传输中立的 method/URL/outcome/status/proto/duration/size/error、请求/响应头与可选 Body、`*core.Redactor`、`Policy`。
- **脱敏快照策略** `Policy`：
  - 默认 `Snapshots=true, Bodies=false`：保存脱敏后的 URL、请求/响应头（Authorization/Cookie/Set-Cookie 等按 B05 规则处理），不保存正文。
  - 正文必须显式开启 `Bodies`；即便开启，也先经过 `core.Redactor`（含 Base64/URL/JSON/Basic 拼接等变体），并受 `MaxBodyBytes`（默认 64 KiB）限制。
  - 响应已被执行器截断、非文本/multipart/二进制、超限或策略关闭时，只记录 `BodySize` 与 `Omitted` 原因，不落盘正文。
  - 名称、环境、URL、错误文本也经过同一 Redactor，避免秘密通过拼接或编码泄漏。
- **过滤** `localstate.Filter`：时间区间、项目键、接口 ID、结果分类（success/client/server/network/canceled/timeout）、自由文本（方法/URL/请求名/项目名/环境）。
- **上限与清理** `Limits`：默认 500 条、2 MiB/项目、单条 512 KiB、保留 90 天；桌面设置可选 30/90/365 天或不按期限删除。每次追加与显式打开都执行保留期/条数/总字节裁剪；单条过大时先丢弃可选快照，仍超限则返回 `ErrRecordTooLarge` 且不写盘。
- **可诊断失败**：
  - `Load` 跳过损坏行并计数，旧的有效记录仍返回；`LoadResult.Diagnostics` 携带路径、大小、损坏行数、读取错误。
  - `Append` 返回重写时丢弃的损坏行数；重写失败返回 `WriteError{Path, Err}`，读取失败返回 `ReadError{Path, Err}`；`errors.Is(err, os.ErrPermission)` 可判定权限问题。
  - 写入采用同目录临时文件 + `0600` + fsync + rename；失败不会留下半行记录。历史目录按 `0700` 创建。
  - `safeKey` 拒绝键名中的路径穿越/隐藏文件。
- **并发**：单进程内同一 `Store` 的追加/删除/清理由互斥锁串行化，测试以 8×25 并发追加验证无损坏行、无重复 ID、无临时文件残留。跨进程（同时运行两个应用实例）未加文件锁，后写者按原子 rename 生效；见限制。

### 1.3 桌面接线

`internal/desktop/history.go` 重写为适配层 + 视图：

- 发送成功 → `recordHistory`：使用 `BuildTrackedPlanWithOptions` 返回的 Redactor 和完整 `Plan`（含 `plan.Query` 合并后的实际 URL）生成脱敏记录。
- 发送失败/取消/超时 → `recordHistoryFailure`：按外部 context（`Canceled`/`DeadlineExceeded`）与 core 的超时消息分类；不伪造状态码或响应。
- 历史面板新增：
  - 范围：本项目 / 全部项目；全部项目下可按具体项目下拉筛选。
  - 时间：全部 / 今天 / 最近 7 天 / 最近 30 天。
  - 结果：全部 / 成功 / 客户端错误 / 服务端错误 / 网络或配置错误 / 已取消。
  - 接口：按方法、URL、请求名、项目名、环境的文本筛选。
  - 诊断行：损坏行、读取失败、写入失败、快照被裁剪。
  - 隐私说明：历史只在本机；默认仅脱敏元数据，正文需显式开启。
- 快照预览：行内 `i` 按钮打开详情，显示概要、脱敏请求/响应头与可选正文、正文未保存原因；详情中提供“打开请求 / 删除此记录 / 关闭”。“打开请求”使用脱敏后的 URL（不会把真实秘密写回编辑器）。
- 全部项目视图下的归属正确性：删除记录写入该记录所属项目文件；恢复其他项目的记录时，若该项目窗口已打开，则在该窗口打开请求并填入脱敏 URL；项目未打开时明确提示，不把 URL 套到当前项目的标签。清除历史始终只作用于本项目，并在全部项目视图隐藏清除按钮，避免一次点击清掉多个项目。
- 设置面板新增“本地历史”：保存脱敏快照、快照包含正文（已脱敏、有上限）、保留期限。设置写入本机 `config.json`，不进入项目或 Git。

## 6. 接口提案（给 A01/B04 接线）

B04 尚未合入，本卡按当前 `core.Plan`/`core.ExecResult` 口径适配，不新增网络引擎。未来 Runner/传输层可直接填充：

```go
type HistoryInput struct {
    Ts time.Time
    ProjectKey, ProjectName string
    RequestID, RequestName, Environment string
    Method, URL, Outcome string
    Status int
    Proto string
    Duration time.Duration
    SizeBytes int64
    Error string
    RequestHeaders [][2]string
    RequestBody []byte
    RequestContentType string
    ResponseHeaders [][2]string
    ResponseBody []byte
    ResponseTruncated bool
    Redactor *core.Redactor
    Policy Policy
}
```

建议 Runner 侧：
- 每个请求/步骤产生一条记录时填充同一字段；`Outcome` 使用 `ok|error|canceled|timeout`。
- 若有 Cookie/Set-Cookie、阶段耗时、重定向等新结果字段，先在该结构中增加可选字段（例如 `StageDurations`），再在 `BuildRecord` 中决定是否持久化；不要把 Cookie 值或原始大 Body 默认写入历史。
- 若 B04 提供解压后大小/传输大小双口径，`SizeBytes` 保持当前“展示/正文大小”语义，新增字段作为接口提案，不与现有字段混用。

## 7. 剩余项与限制

1. **真实窗口人工验收未做**：筛选下拉、详情弹窗、删除/恢复的鼠标交互由 `ui.NewTester` 无窗口测试覆盖，未在真实 macOS 窗口点击验收；Windows/Linux 未实机验证。
2. **跨进程并发未加锁**：同一进程内串行且原子写；两个应用实例同时写同一项目历史时，最后一次 rename 生效，可能丢失另一实例刚追加的记录。当前产品为单实例窗口应用，未引入文件锁；如需多实例需另立接口。
3. **正文捕获是选择性的**：默认不存正文；multipart/octet-stream/非 UTF-8 一律视为不可安全展示而省略；上限 64 KiB/正文。不宣称“完整响应归档”。
4. **恢复使用脱敏 URL**：历史中的 URL 已脱敏，点击恢复会把 `***` 写回编辑器并标记 Dirty；这是有意避免秘密回填。若需要“原始模板 URL”，应保存未解析模板并在恢复时重新解析，属于后续增强。
5. **旧记录无快照**：升级前的元数据记录没有请求/响应快照，详情只显示概要。
6. **全部项目视图不做跨项目自动清理**：按项目打开时执行保留期/条数/字节清理；“全部项目”只读合并，不会批量改写其他项目文件。清除按钮在该视图隐藏，删除仍按记录所属项目精确执行。
7. **项目筛选**：提供“本项目/全部项目”以及全部项目下的具体项目下拉；不提供跨设备历史同步。
8. 未修改总账本和 `implementation-status.md`，不自行勾选整卡完成；集成人需按验收流程决定。
9. `internal/localstate` 依赖 `internal/core`，因此继承 core 现有的纯 Go MyGo Markdown parser 传递依赖（无 GUI/窗口依赖）；本卡未新增任何 MyGo 依赖。
