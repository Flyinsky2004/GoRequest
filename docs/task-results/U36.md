## 2. 实际改动

### 2.1 Secret 默认存储改为本地文件，保留显式 Keychain 选择（`fc35d81`）

- `internal/platform/secret_store.go`：
  - `SecretStore.SelectedKind(scope)` 在 `preferences.json` 不存在或该 `scope` 未持久化显式后端选择时默认返回 `SecretBackendFile`（`"file"`），不再默认选择系统钥匙串。
  - `SecretBackendKind.String()` 未设置/零值回退改为 `"file"`。
  - 已显式持久化 `"keychain"` 的项目 `scope` 重启后原样保留 `SecretBackendKeychain`；不会在打开项目时自动迁移真实秘密或静默切换已选后端；损坏或非法版本的 `preferences.json` 仍保持 fail-closed 返回配置错误。
- `internal/platform/secret_file.go`：同步注释说明本地文件后端为默认存储（`0700`/`0600` 明文 JSON，不伪称加密）。
- `internal/desktop/identity_management.go`：`secretBackendInfo` 与 `secretBackendKind` 在无受管凭据实例时的回退值对齐为 `platform.SecretBackendFile`。
- 测试（`internal/platform/secret_store_test.go`、`internal/desktop/secret_storage_test.go`、`internal/desktop/secret_storage_integration_test.go`、`internal/desktop/secret_entry_test.go`、`internal/desktop/identity_management_test.go`）：
  - 验证新项目默认选中本地文件后端、不触碰 Keychain 驱动、不自动迁移已有值；
  - 验证显式切换到 Keychain 后写入 `preferences.json` 并在重新打开时保留 `SecretBackendKeychain`；
  - 原专门验证 Keychain 驱动不可用/轮换行为的集成测试通过显式选中 Keychain 保持覆盖语义。

### 2.2 历史记录完整未脱敏保存模式与无二次截断持久化（`ce8f8f9`）

- `internal/localstate/history.go`：
  - 新增 `Policy.Unredacted`、`FullPolicy()`、`FullLimits()`、`FullMaxRecordBytes`（256 MiB）、`FullMaxBytes`（512 MiB）、`OmitStream`（`"stream"`）、`BodyEncodingUTF8`（`""`）与 `BodyEncodingBase64`（`"base64"`）。
  - `Snapshot` 新增 `BodyEncoding`、`IsBinaryBody()` 与 `BodyBytes() ([]byte, error)`：合法 UTF-8 文本原样写入 `Body`；含 NUL、非 UTF-8 或非文本二进制负载以标准 Base64 无损保存，`BodyBytes()` 精确还原原始 `[]byte`（避免 JSON 序列化将非 UTF-8 字节替换为 `U+FFFD`）。
  - `Record` 新增 `Unredacted`、`SnapshotTrimmed`、`IsUnredacted()`、`HasFullSnapshots()`：旧脱敏记录与默认模式记录 `Unredacted == false`，永不冒充完整记录。
  - `BuildRecord` 在 `p.Unredacted` 开启时：保留原始 URL（含 userinfo 与 query token）、原始有序重复请求/响应头（`Authorization`、`Cookie`、`Set-Cookie`、`X-Api-Key` 等）、完整请求/响应正文（不受 `DefaultMaxSnapshotBody` 64 KiB 限制、不因二进制被省略）以及原始失败错误信息。
  - 诚实记录捕获界限：
    - 网络/执行层已截断响应（`ResponseTruncated == true`）：无损保存已捕获前缀字节并保留 `Response.Truncated = true`，`HasFullSnapshots()` 返回 `false`；
    - 未缓冲流式上传正文（`RequestHasBody && RequestBody == nil` 或 `RequestBodyStreamed == true`）：标记 `Request.Omitted = "stream"` 并记录 `RequestBodySize` / `Content-Length`，不把空 `plan.Body` 冒充为已完整保存上传体；
    - 若调用方显式配置了极小 `MaxRecordBytes` 触发快照裁剪，落盘写入 `SnapshotTrimmed = true`，绝不宣称 `HasFullSnapshots()`。
  - 消除 `Store` 二次 trim 与读取上限：
    - `Limits` 区分默认回退上限与显式自定义上限，`Unredacted` 记录在默认 Store 上限或 `FullLimits()` 下使用 `FullMaxRecordBytes`（256 MiB）/ `FullMaxBytes`（512 MiB），不会在 `Append` 或 `Cleanup`/`prepare` 阶段被 512 KiB / 2 MiB 默认上限悄悄清空快照；
    - `Store.loadLocked` 改为直接在字节切片上按 `\n` 扫描 JSONL，移除 `bufio.Scanner` 固定缓冲上限对数 MiB 大记录的读取截断/报错；
    - `Store.writeAllLocked` 流式逐行写入临时文件并 `Sync` + `0600` 原子重命名；保留原有 retention 天数清理、`MaxRecords`、`Cleanup`、`Remove`、`Clear` 与克隆目录隔离。
- `internal/desktop/config.go`、`internal/desktop/settings.go`、`internal/desktop/i18n.go`：
  - `historyPrefs` 新增 `FullCapture *bool`（`json:"fullCapture,omitempty"`）及 `historyFullCapture()` / `setHistoryFullCapture(bool)`，未配置时默认关闭（保持原默认脱敏策略）。
  - 设置 -> 历史记录分类新增直接勾选开关“保存完整未脱敏数据（原始 URL、请求头、二进制与大正文）”（无额外确认弹窗）；开启时禁用仅适用于脱敏模式的元数据/64 KiB 文本正文复选框并展示说明文案，保留保留期限选择器，340 DIP 窄宽度下无水平溢出。
- `internal/desktop/history.go`：
  - `historyPolicy()` / `historyLimits()` 按 `historyFullCapture()` 切换 `localstate.FullPolicy()` 与 `localstate.FullLimits()`（叠加用户配置的保留天数 `30`/`90`/`365`/`-1`）。
  - `historyInput` 传入 `RequestHasBody: plan.HasBody`；`effectivePlanURL` 在 URL 含特殊字符导致 `url.Parse` 失败时仍补齐 `plan.Query`，避免丢失原始 query 参数。
  - 历史侧栏底部隐私提示按当前设置区分脱敏提示与完整未脱敏提示。
  - 历史详情弹窗新增“记录模式”行（`已脱敏` / `完整未脱敏` / `未脱敏（部分捕获）` / `未脱敏（快照已裁剪）`）及底部真实状态说明：即使当前已开启完整模式，旧脱敏记录依然明确显示为“已脱敏”；二进制正文显示无损字节大小与前 64 字节 hex 预览；超大文本在 UI 中仅缩略预览（16 KiB / 380 行）并注明完整字节已保存在本地历史文件中，磁盘数据不截断。
- 专项测试：
  - `internal/localstate/history_full_capture_test.go`：覆盖默认脱敏回归、完整未脱敏 URL/query/userinfo/重复敏感头/错误信息原值、`Store.Append` -> 新实例 `Store.Load` -> `Cleanup` 往返下 1.5 MiB 大文本与 1.2 MiB 二进制（含全 256 字节值与 NUL）逐字节无损还原、网络截断前缀保留与 `Truncated` 标注、流式上传 `OmitStream` 界限、旧脱敏记录与新完整记录并存区分、显式小上限 `SnapshotTrimmed` 标注及 Retention 清理。
  - `internal/desktop/u36_secret_history_test.go`：覆盖 `configStore` 持久化与默认关闭、中英文设置页直接开关与 340 DIP 窄布局、桌面端从默认脱敏 -> 开启完整未脱敏（含 200 KiB 请求体、180 KiB 二进制响应体、网络截断响应、未缓冲流式上传、失败错误原值）-> 重载 Store -> 历史详情弹窗真实区分旧脱敏记录与新完整/部分捕获记录，且项目源文件零改动。

## 4. 捕获界限、已知限制与跨归属说明

1. **未触碰真实环境与实机窗口**：全部验证基于临时目录、`ui.Tester` headless 渲染与内存 fake Keychain 驱动完成，未启动真实桌面窗口，未读写系统真实 Keychain 或用户全局配置目录。
2. **网络截断与流式上传的真实界限**：
   - 响应超过执行器读取上限（`ResponseTruncated == true`）时，网络未接收的尾部字节无法凭空补回；本地历史无损保存已接收前缀字节，并在记录与详情 UI 中如实标注网络截断边界。
   - 请求使用未缓冲流式上传（`Plan.HasBody == true && Plan.Body == nil`）时，按要求未改执行器缓冲整段上传流，记录 `Omitted = "stream"` 及已知字节长度并在详情 UI 中如实提示。
3. **跨归属边界说明（无需额外 patch）**：
   - 集成人已在 `d6bf54a` 补齐执行链路：完整本地历史启用独立 `UnredactedResult` 输出选项，SSE 聚合体与执行错误原值可进入历史；仍保留执行器 Redactor 注册 Secret/Cookie、剥离跨域敏感头的行为。Runner/diagnostics 共用选项不启用此标志。发送后才开启设置的旧请求不会被误标为原始捕获。loopback SSE -> 执行 -> 保存 -> 重载、错误原值、跨域敏感头过滤与默认脱敏回归均有测试。
