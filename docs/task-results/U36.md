## 2. 默认 `File` 存储与保留显式 `Keychain` 选择（`fc35d81`）

### 2.1 行为与持久化规则

| 场景 | `preferences.json` 状态 | 实际选中后端 | 说明 |
| --- | --- | --- | --- |
| 新项目 / 从未切换存储位置 | 文件不存在，或 `scopes[scope]` 为空 | `SecretBackendFile`（`"file"`） | 默认使用 `~/.gorequest/secrets/store-<scope>.json`（目录 `0700`、文件 `0600`，UI 明示本地明文文件、不伪称加密） |
| 用户已显式选择系统钥匙串 | `scopes[scope] == "keychain"` | `SecretBackendKeychain`（`"keychain"`） | 重启与重新打开项目时原样保留 `"keychain"`，不被新默认值覆盖 |
| 用户已显式选择本地文件 | `scopes[scope] == "file"` | `SecretBackendFile`（`"file"`） | 原样保留 |
| 偏好文件损坏 / 版本不支持 / 未知后端值 | JSON 损坏、`version != 1` 或非法枚举值 | 返回 `ConfigError`（fail-closed） | 绝不静默回退到另一存储后端或覆盖已有偏好 |
| 打开已有项目 | 任意 | 不自动迁移秘密值 | 仅在用户主动执行“更改存储位置”操作时才复制并校验受管凭据；默认打开项目不触碰 Keychain 驱动 |

## 3. 历史完整未脱敏保存、本地 `256 MiB / 512 MiB` 边界与真实捕获标识（`ce8f8f9`）

### 3.1 策略与无损序列化设计

- **默认策略不变**：未启用“保存完整未脱敏数据”时仍使用 `DefaultPolicy()` + `DefaultLimits()`（仅脱敏元数据快照、正文默认关闭、开启脱敏正文时维持 `64 KiB` 与纯文本检查、单条上限 `512 KiB`、单项目文件上限 `2 MiB`）。
- **完整未脱敏策略（`FullPolicy()` + `FullLimits()`）**：
  - 设置 -> 历史记录分类新增直接复选框 `HistoryFullCapture`（持久化于 `config.json` 的 `history.fullCapture`，无额外确认弹窗；开启时禁用仅适用于脱敏模式的两个子复选框，保留 `30 / 90 / 365 / 不限` 保留期选择）。
  - `BuildRecord` 在 `Policy.Unredacted == true` 时跳过 `Redactor` 与 `64 KiB` / 文本限制，原值保存：
    - 请求 URL（含 userinfo 凭据与敏感 query 参数；补充了 `effectivePlanURL` 在特殊字符导致 `url.Parse` 失败时的 query 拼接兜底）；
    - 完整有序请求头与响应头（含重复同名头、`Authorization`、`Cookie`、`Set-Cookie`、`X-Api-Key` 等原值）；
    - 请求与响应正文：合法 UTF-8 且不含 NUL 字节的文本直接存 `Body`（`BodyEncoding: ""`）；二进制、含 `\x00` 或非 UTF-8 字节序列采用标准 Base64 存 `Body`（`BodyEncoding: "base64"`），由 `Snapshot.BodyBytes()` 逐字节无损还原；
    - 失败请求的原始 `Error` 文本。

### 3.2 `256 MiB / 512 MiB` 本地存储边界与防二次截断机制

| 维度 | 默认脱敏模式（`DefaultLimits`） | 完整未脱敏模式（`FullLimits` / 默认 Store 写入 `Unredacted` 记录） | 超界时的精确行为 |
| --- | --- | --- | --- |
| 单正文捕获上限（`MaxBodyBytes`） | `64 KiB`（`DefaultMaxSnapshotBody`） | 无 `64 KiB` 截断（受单条记录总上限约束） | 默认模式超 `64 KiB` 记 `omitted: "large"`；完整模式完整写入 |
| 单条 JSONL 记录上限（`MaxRecordBytes`） | `512 KiB`（`DefaultMaxRecordBytes`） | **`256 MiB`（`FullMaxRecordBytes`）**（Base64 约 `4/3` 编码膨胀下约合 **`~192 MiB`** 原始二进制负载） | 若单条序列化后超 `MaxRecordBytes`：`Store.Append` 剥离 `Request`/`Response` 快照并将 **`Record.SnapshotTrimmed = true`**、`AppendResult.Trimmed = true` 落盘（绝不伪装成完整快照）；若仅元数据仍超上限，返回 `ErrRecordTooLarge` 且不改写现有历史文件 |
| 单项目历史文件总上限（`MaxBytes`） | `2 MiB`（`DefaultMaxBytes`） | **`512 MiB`（`FullMaxBytes`）** | `Store.prepare` / `Cleanup` 始终完整保留最新记录，累计字节超过 `512 MiB` 时整条淘汰更早的旧记录，**绝不二次删减已保留记录中的请求/响应正文** |
| 条数与保留期（`MaxRecords` / `Retention`） | `500` 条 / 默认 `90` 天 | `500` 条 / 按设置保留期（`30`、`90`、`365` 天或 `-1`） | 与原保留期清理、`Remove`、`Clear`、克隆路径哈希隔离完全兼容 |
| JSONL 读取扫描器 | 按 `\n` 直接切片扫描 | 按 `\n` 直接切片扫描（无 `bufio.Scanner` `64 KiB` token 限制） | 数 MiB 乃至百 MiB 级单行 JSONL 记录在 `Store.Load` / `LoadAll` / `Cleanup` 时完整重载，不报 token 过长或丢行 |
| 磁盘写入方式 | 临时文件流式逐行写入 + `Sync` + `0600` + `Rename` | 同左 | 原子落盘，不在内存中重复拼接整块多倍缓冲区 |

### 3.3 未捕获上传流、网络截断与旧脱敏记录的真实标识对照

| 记录实际状态 | 触发条件 | 落盘 JSON 关键字段 | `IsUnredacted()` / `HasFullSnapshots()` | 历史详情弹窗“记录模式”与提示 |
| --- | --- | --- | --- | --- |
| **已脱敏记录**（含历史遗留旧记录） | 默认模式写入，或旧版 JSONL 无 `unredacted` 字段（即使当前设置已开启完整模式） | `unredacted: false`（缺省），`request.redacted: true` | `false` / `false` | `已脱敏` / `Redacted`，底部显示脱敏隐私说明，**旧脱敏记录绝不冒充未脱敏** |
| **完整未脱敏记录** | 完整模式写入，请求/响应均完整捕获且未触发记录裁剪 | `unredacted: true`，`redacted: false`，无 `truncated` / `omitted` / `snapshotTrimmed` | `true` / `true` | `完整未脱敏` / `Full unredacted`，显示未脱敏原始数据说明（二进制含字节数 + 前 64B hex 预览；超 `16 KiB` / `380` 行文本仅在 UI 预览缩略并提示磁盘已存完整字节） |
| **未捕获流式上传边界** | `Plan.BodyStream` 流式上传导致 `Plan.HasBody == true && Plan.Body == nil`（或 `RequestBodyStreamed == true`） | `unredacted: true`，`request.omitted: "stream"`，`request.bodySize` 记录已知长度或 `Content-Length` | `true` / **`false`** | `未脱敏（部分捕获）` / `Unredacted (partial capture)`，请求快照显示省略原因 `上传正文以流式发送，未在内存中缓冲`，底部显示 `HistoryStreamBoundaryNote`，**不把空 `plan.Body` 冒充为已完整保存上传体** |
| **网络/执行层已截断响应边界** | 响应超过执行器读取上限（`ResponseTruncated == true`） | `unredacted: true`，`response.truncated: true`，已接收前缀字节仍按 UTF-8 / Base64 无损写入 `response.body` | `true` / **`false`** | `未脱敏（部分捕获）` / `Unredacted (partial capture)`，正文尾部标注已保存前缀字节数并提示网络层未接收的尾部无法补回，底部显示 `HistoryTruncatedBoundaryNote` |
| **单条超上限裁剪记录** | 单条序列化超过 `MaxRecordBytes`（完整模式下 `> 256 MiB`，或测试显式指定极小上限） | `unredacted: true`，`snapshotTrimmed: true`，`request: nil`，`response: nil` | `true` / **`false`** | `未脱敏（快照已裁剪）` / `Unredacted (snapshots trimmed)`，底部显示 `HistorySnapshotTrimmed` |
