## 实现

### 1. 出厂默认 55:45

- `internal/desktop/layout_split.go`（新增）
  - `defaultBuildPct = 55`、`minBuildPct = 20`、`maxBuildPct = 86`、`minResponseHeight = 180`。
  - `clampBuildPctForHeight(pref, splitHeight)`：按上一帧已提交的分栏高度计算请求区可占的最大比例，保证响应区 ≥180 DIP；首帧无测量值时不钳制。
  - `applyBuildPctMove(pref, passed, moved)`：把用户拖动产生的差值叠加到偏好上，而不是用钳制后的布局值覆盖偏好。
- `internal/desktop/config.go`
  - `buildPct()` 无有效值时返回 55（原 64）；读写范围改用共享常量。
- `internal/desktop/project_state.go`
  - 新项目 `buildPct`/`layoutPct` 初始化为 55；新增 `splitRef`/`respRef` 两个 `ui.Handle` 用于读取已提交几何。
- `internal/desktop/workspace.go`（仅 `requestView` 分栏区域）
  - 每帧把 `clampBuildPctForHeight(ps.buildPct, splitRef.Bounds(c).H)` 的临时有效值交给 `ui.SplitVerticalPercent`。
  - 分栏控件只会把用户拖动写回 `layoutPct`；检测到 `layoutPct != eff` 时用差值更新并持久化偏好。布局钳制（`eff != buildPct`）不写回。
  - 双击分栏恢复 55:45，并同步持久化。
  - 响应面板外包一层 `Grow(1).FillHeight()` 的 Column 并绑定 `respRef`，不修改 `response_view.go`（该文件归 R7/R8）。

### 2. Split API 核对

MyGo v0.7.4 `ui.SplitVerticalPercent`（`ui/split.go`）只提供固定最小面板 `t.Space(10)`（默认 Spacing=4，即 40 DIP），没有“响应区最小高度”参数；`*p` 只在拖动/方向键时被写回。因此最小高度保护必须在调用侧按已提交高度计算临时比例，不能只改默认值。

### 3. 旧比例与持久化

- 旧配置中的合法 `buildPct`（如 70）原样恢复；窗口足够高时按 70% 布局。
- 窗口不足时按响应区 180 DIP 临时压缩请求区，但偏好仍保持 70，不写回配置。
- 拖动比例跨启动持久化（`configStore.setBuildPct`）。
