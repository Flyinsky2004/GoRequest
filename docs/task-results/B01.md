## 1. 实际实现范围

### 1.1 存储边界、可恢复 `ChangeSet` 与文件同步引擎（Core）
- **存储安全与资源上限（`internal/core/store.go`）**：
  - 增加 `StoreLimits`（默认单 YAML 上限 `1 MiB`、单 Markdown 文档上限 `8 MiB`、跟踪文件数上限 `10,000`）与 `ReadBounded`、`RemoveChecked`、`ResolvePath`；
  - 修复并加固 `Store.resolve` 与 `Store.List` 的符号链接检查：逐段 `Lstat` + `EvalSymlinks` 校验，同时拒绝**指向仓库外的符号链接**与**悬空（dangling）符号链接**，并兼容 macOS `/var -> /private/var` 根目录映射；
  - 增加 `DetectGitConflictMarkers` / `HasGitConflictMarkers`（检测 `<<<<<<<` / `|||||||` / `=======` / `>>>>>>>`）、`NormalizeLF`、`IsTempOrIgnoredName`（过滤 `.tmp-*`、`*.swp`、`*.bak`、`*~`、`.DS_Store` 等临时噪声）。
- **多文件可预览与可回滚 `ChangeSet`（`internal/core/changeset.go`）**：
  - 支持 `Create` / `Update` / `Delete` / `Move` 四类操作及提交前 `Preview()`；
  - 执行前统一校验路径越界、大小限制、基线摘要冲突（拒绝覆盖外部改动或复活已变更文件）与未解决 Git 冲突标记；
  - `Apply()` 期间任一步骤失败自动逆序回滚磁盘状态，成功返回 `ChangeReceipt` 支持显式 `Rollback()`，且不在 `.gorequest/` 下残留 `.bak` 或 `.tmp-*` 文件。
- **快照差分与三版本同步引擎（`internal/core/file_sync.go`）**：
  - `ScanDiskSnapshot` 与 `DiffSnapshots`：确定性识别请求、集合、环境、鉴权、项目文件与文档的 `SyncCreated`、`SyncModified`、`SyncDeleted`、`SyncRenamed`（优先按稳定 `id` 配对更名/移动，其次按同类型内容摘要或高重合度单文档配对）；
  - `SyncEngine.ScanAndSync`：
    - **干净缓冲**：外部修改自动原地刷新内存模型并保留既有 `*RequestEntry` 指针；外部纯更名/移动自动更新路径与集合继承变量；外部删除通知关闭干净标签且不写盘；
    - **脏缓冲保护**：外部修改、外部删除、外部更名并修改均隔离为三版本 `SyncConflict`（同时完整保留 `BaselineBytes` 读取基线、`DiskBytes` 磁盘当前版本、`EditedBytes` 当前未保存编辑），绝不静默覆盖任一方；
    - **外部更名不复活旧路径**：脏缓冲遇外部纯更名自动跟随新路径，遇外部更名+修改在记录 `OldPath -> RelPath` 的同时将后续解决目标绑定到新路径，旧路径绝不被重新写出；
    - **防复活删除文件**：`CanAutoSave` 在存在未决冲突、磁盘文件已删除或摘要不一致时一律返回 `false`，阻止自动保存定时器复活被外部删除的文件；
  - `MergeThreeWay` 与 `ResolveConflict`：内置基于 LCS 的行级三方合并（非重叠改动自动无损合并，重叠改动生成 diff3 冲突块并禁止直接落盘），支持 `reload-disk`、`accept-delete`、`keep-edited`、`apply-merged`、`save-as-copy`（自动分配新稳定 `id` 与副本文件名，保留双方），并防护解决期间发生的**第三次外部并发写入**。
- **监听风暴合并器（`internal/core/file_watcher.go`）**：
  - `StartWatcher` / `ProjectWatcher`：结合有界树摘要扫描与非阻塞 `Trigger()` 信号通道，按 `DebounceWindow`（默认 `80ms`）与 `MaxBatchWait`（默认 `500ms`）将高频外部写入/分支切换风暴合并为稳定批次通知，并通过 `AcknowledgeCurrent()` 抑制自身保存回环，全程零网络访问、零磁盘写入。

### 1.2 注释/格式保真写回与严格 YAML AST 审计（Core）
- **严格 YAML AST 与资源审计（`internal/core/yaml_strict.go`）**：
  - `ParseStrictYAMLTree`：强制校验合法 UTF-8、拒绝 NUL 字节、拦截未解决 Git 冲突标记、强制单 YAML 文档，限制 AST 最大嵌套深度（默认 `64`）、最大节点数（默认 `50,000`）与别名展开累计节点开销（默认 `100,000`，防御 Billion Laughs 指数膨胀），拒绝 `<<` merge key，并在**所有映射层级**（含 `AuthRef` 与 `Body` 自定义 `UnmarshalYAML` 子树）拦截重复键；
  - `ValidateEntityYAML` / `AuditProjectStrict` / `OpenProjectStrict`：补齐 `gopkg.in/yaml.v3` 在自定义 `UnmarshalYAML` 子树中丢失 `KnownFields(true)` 的缺口（拒绝 `auth` 同时含 `ref` 与内联字段、拒绝内联 `auth` 未知字段、拒绝 `body` 同时含 `file` 与 `value`、拒绝 `extensions` 非映射类型、拒绝高于当前支持版本的 `schemaVersion`）。
- **注释与格式保真合并写回（`internal/core/yaml_preserve.go`）**：
  - 提供 `MergeRequestYAML`、`MergeEnvironmentYAML`、`MergeCollectionYAML`、`MergeProjectFileYAML` 及对应的 `*Project` 保真保存方法 `SaveRequestPreserving`、`SaveEnvironmentPreserving`、`SaveCollectionPreserving`、`SaveProjectFilePreserving`；
  - 基于 `yaml.Node` AST 最小增量修补：未改动子树原样保留，完整保留文件头/行内/尾部注释、原有字段顺序、引号与流式风格、`KV` 项显式 `enabled: true`、JSON `body.value` 内的块级 YAML 写法与内部注释（采用顺序无关 JSON 语义比对避免无谓重写），以及顶层 `extensions` 扩展块；拒绝将高 `schemaVersion` 文件降级写回。

### 1.3 MyGo Native UI 同步控制器与三版本冲突界面（Desktop）
- **同步与保存控制器（`internal/desktop/file_sync.go`）**：
  - 为每个 `*projectState` 维护独立的 `fileSyncController`，支持 `InitFileSync`、`StartFileSync`、`StopFileSync`、`SyncNow`、`AutoSaveTick`、`CanSendTab`、`saveTabSynced` / `saveActiveSynced`、`OpenConflictModal`、`RunThreeWayMergeInModal`、`ResolveTabConflict`；
  - 后台监听回调严格经 `win.Update` 回到所属项目窗口 UI 线程，并在窗口关闭/销毁后立即丢弃回调与释放协程；
  - 即使请求表单正处于半输入状态（如未闭合 JSON Body 或未填键名的 KV 行），后台冲突捕获仍通过 `bestEffortRequestFromTab` 完整保留用户输入，不丢失草稿；
  - 当活跃环境或请求文件存在未解决 Git 冲突标记时，保持当前环境选中（不静默切走环境）并通过 `CanSendTab` 阻断发送。
- **原生冲突横幅与三版本合并模态框（`internal/desktop/file_sync_ui.go`, `internal/desktop/file_sync_i18n.go`, `internal/desktop/workspace.go` 独占区 4 行挂接）**：
  - 无冲突时零 UI 节点、零空闲动画帧请求（通过帧预算守卫验证）；
  - 发生脏冲突时在标签页顶部展示警告横幅，支持一键打开三版本模态框、重新加载磁盘版、接受删除并关闭、另存为副本；
  - 三版本模态框支持 **“三版本对照”**（读取基线只读 + 磁盘版本只读/删除说明 + 编辑合并结果可编辑）、**“基线 ↔ 磁盘差异”**（原生 `editor.DiffView` 分栏只读对比）、**“磁盘 ↔ 编辑合并”**（原生 `editor.DiffView` 可编辑分栏 + hunk 操作）三种模式切换，完整支持简体中文与英文实时切换。
