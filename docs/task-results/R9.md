### 复现（基线 `7874b0b` 干净归档 + 本项测试）

把 `send_status_test.go` 放入基线归档后运行：

结论：发送开始时写入“正在发送…”，完成回调只更新标签页字段，从不写回状态栏，因此成功、失败、取消三种结束路径都永久停留在“发送中”。这是真实残留，不是预设缺陷。

### 异步保存 / 文件同步 / 旧请求回调

- `AutoSaveTick` 不写 `a.status`；`saveActiveSynced` 是同步调用，只在用户手动保存时覆盖状态，属于独立用户动作。
- 文件同步的外部修改/删除/更名提示走 `fileSyncMessages` 的独立 banner 字段，不写 `a.status`。
- 旧请求回调：`send()` 现在为每次发送递增 `Tab.sendSeq`，完成回调只接受 `tab.sendSeq == seq` 的结果。正常路径下 `Sending` 已串行化发送，但窗口销毁等强制复位可能让旧回调晚到；序号守卫会丢弃它，避免旧响应/旧状态覆盖新发送。
