## 1. 实现选择

### 1.1 环境选择器与 “+” 新建菜单：应用窗口内绘制的主题菜单

核对 `github.com/egoist/mygo@v0.7.4` 的真实实现：

- `ui.MenuButton` → `menuButton(...).Menu(build)`，走 `rt.openMenu`，即**系统原生菜单**。
- `ui.PopoverMenuButton` → `menuButton(...).PopoverMenuButton(build)`，走 `rt.drawMenu`，在窗口 overlay 内绘制面板；面板使用 `ui.Theme` 的 `Background/Border/Text/TextMuted/Accent/AccentText/SurfaceHover`，并自带键盘（方向键/Home/End/Enter/Space/Escape）、焦点进入与归还、点击菜单外关闭、勾选/禁用绘制。
- `uikit.Select` 基于 `ui.SelectBase`，同样是应用内弹层；但它是“单选列表”语义，而环境菜单包含禁用预览行、分隔线、勾选切换与“编辑/新建”动作，`PopoverMenuButton` 的菜单语义更贴合，且能原样复用现有 `build` 函数。

新增专属模块 `internal/desktop/header_menus.go`：

- `headerMenuButton(c, p, label, build)`：用 `ui.ButtonBase` + palette 绘制触发器（`Sidebar` 面色、`Hover/Press` 悬停按下、`Hairline` 边框、`Text` 标签、`Muted` chevron），再调用 `PopoverMenuButton(build)`。
- 菜单构建函数完全沿用原 `envMenu` / `buildNewMenu` 的内容：环境变量预览（禁用）、`(none)` 与各环境（`Checked`）、分隔线、`Edit Env`（`Disabled(!canEditEnv())`）/`New Env`；新建菜单的 Request/Folder/Doc/Env 与 interop 导入项。
- 未新增颜色 token；触发器与弹层都来自现有 palette / `uikit.Theme`，亮暗主题一致。

`workspace.go` 改动：

| 位置 | 改动 |
| --- | --- |
| `workspaceHeader` | `+` 菜单由 `ui.MenuButton` 改为 `headerMenuButton`；环境选择器右侧新增 `a.saveControl(c, p, ps.activeTab())`。 |

项目名切换菜单（`buildProjectMenu`）保持原生菜单不变——用户本次只点名“环境/新建(+菜单)”，且该函数不在本任务归属范围。

### 1.2 保存按钮

- **位置**：`workspaceHeader` 中紧跟 `envMenu`，即环境选择器右侧、同一行。
- **显示条件**：`tab == nil || !tab.Dirty` 时直接不渲染。请求标签由编辑动作置 `Dirty`；文档标签在 `docWorkspaceView` 中由 `DocEditor.Buffer.Modified()` 镜像到 `Tab.Dirty`（既有语义，未改）。
- **保存后消失**：`saveActiveSynced` 成功后 `saveTabSynced` 清除 `Dirty`，下一帧不再渲染；冲突/失败时 `Dirty` 保留，按钮继续显示。
- **切换标签**：头部每帧读取 `ps.activeTab()`，因此切换标签后按新标签自身的 `Dirty` 显示/隐藏。
- **Cmd+S / 同步 / 冲突**：未改快捷键；按钮与 `Cmd+S` 共用 `saveActiveSynced`，继续走 file-sync 与三版本冲突弹窗。既有冲突测试 `TestConflictModalRejectsGitMarkersAndSupportsSaveAsCopy` 通过。
