## 1. 实现与接线

### 1.1 持久化模型（core）

- `core.Request` 新增可选 `ws:` 块（`WSDef`）：`subprotocols`、`compression`。旧 YAML 不含该字段时完全兼容；`protocol` 缺省仍为 HTTP。
- WebSocket 请求复用共享请求目标字段：`http.url`、`http.query`、`http.headers`、`auth`、`timeout`。`http.method` 固定为显示标签 `WS`，只用于树/标签识别，**不会**作为 HTTP 方法发送。
- `core.NewWebSocketRequest` 与 `NewRequest` 共用同一创建/去重/落盘路径；新请求默认 `protocol: websocket`、`http.url: {{wsUrl}}`。
- 校验允许 `protocol: websocket`：要求 URL 非空、`method` 为 `WS`、子协议非空；未知协议仍报错。
- `BuildPlanWithOptions` 明确拒绝把 WebSocket 请求当 HTTP 执行，防止 runner/HTTP 发送路径误发。
- `core.ApplyAuthToHandshake` 复用 HTTP 的 bearer/basic/apikey 鉴权语义，把解析后的头/查询参数交给握手；解析值只存在于内存。

落盘示例（测试实际产物）：

```yaml
schemaVersion: 1
id: socket
name: Socket
protocol: websocket
http:
  method: WS
  url: 'wss://example.test/socket'
  headers:
    - name: Authorization
      value: Bearer {{secret.token}}
      enabled: true
ws: {subprotocols: [graphql-transport-ws, chat], compression: true}
auth:
  schemaVersion: 1
  id: ""
  type: bearer
  token: '{{secret.apiToken}}'
timeout: 45s
```

连接对象、事件、generation、mailbox、redactor 均不落盘；测试断言 YAML 不含 `session`/`mailbox`/`generation`/`redactor`/`OPEN`，且不含解析后的密钥值。

### 1.2 主工作区与标签（desktop）

- WebSocket 标签保持 `Tab.Kind == "request"`，以 `Entry.Request.Protocol == websocket` 区分。因此保存、文件同步、冲突处理、重命名、移动、关闭保护与 HTTP 请求走完全相同的既有路径。
- 每个 WebSocket 标签独占 `Tab.ws *wsTabState`：草稿、连接会话、事件泵 mailbox、generation、确认状态、发送/过滤/详情选择全部按标签隔离。
- 主工作区视图 `wsTabView` 复用现有布局语言：
  - 顶部 URL 行：`WS` 协议徽标、URL 输入、实时状态徽标、Connect/Disconnect。
  - 配置区复用 HTTP 的 Headers KV 编辑器、Auth 编辑器，以及 WebSocket 专属 Settings（子协议、permessage-deflate、总超时）。
  - 下方消息区：方向过滤、时间线、详情/二进制预览、文本/二进制发送、Ping、带码关闭、Clear View、目标策略确认。
  - 环境选择沿用工作区顶栏的环境菜单；URL/Headers/Auth 中的 `{{...}}` 在 Connect 时按当前环境与密钥解析。
- 入口：`+` 新建菜单新增 `New WebSocket`；项目树中的 WebSocket 请求行按协议打开 WebSocket 标签。旧的项目菜单 `WebSocket Session...` 与 `WebSocketModals` 弹层入口已移除。
- 生命周期：关闭标签调用 `wsTeardownTab` 终止会话并失效回调；窗口销毁经 `cancelAllRequests` 终止所有标签的会话。后台回调通过 `weak.Pointer[App]` + 标签指针 + generation + `indexOfTab` 校验路由，绝不写入其他标签。
- 新增独立翻译文件 `internal/desktop/websocket_workspace_i18n.go`（EN/ZH），未修改全局 i18n 大表。

## 3. 限制与未验收项

- **未运行真实窗口**：本任务只使用 headless App、`ui.Tester` 与本地 `httptest` WebSocket server，未启动 MyGo 真实窗口做人工验收；不宣称实机视觉/交互验收。
- **OAuth2/OIDC**：复用 Auth 编辑器并应用 bearer/basic/apikey；OAuth2/OIDC 的运行时 token 注入仍由 HTTP plan 路径负责，WebSocket 握手未接入该流程。继承到 OAuth 默认鉴权的 WebSocket 请求不会自动带 token。
- **Headers 自动提示**：Headers 页复用 HTTP KV 编辑器，其只读自动提示（Host/Accept-Encoding/User-Agent）是 HTTP 语境的展示提示；实际握手只发送用户行与解析后的鉴权头。
- **默认 URL**：新 WebSocket 请求默认 `{{wsUrl}}`；项目未定义该变量时 Connect 会明确报变量解析失败（与 HTTP 的 `{{baseUrl}}` 行为一致）。
- 未新增依赖、未升级 MyGo、未修改 `go.mod`/`go.sum`。
