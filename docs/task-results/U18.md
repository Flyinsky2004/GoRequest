## 2. 实现与接线

### 2.1 可选后端与真实属性

- 默认后端继续是系统 Keychain（macOS Keychain / Windows Credential Manager / Linux Secret Service），不会因为 Keychain 失败自动落到文件。
- 用户可在凭据页显式选择“本地文件（明文）”。文件位于 `~/.gorequest/secrets/store-<slug>-<hash>.json`，按 `<projectSlug>:sha256(规范化项目根)[:16]` 隔离；两个同名仓库的不同克隆得到不同文件。
- 文件后端 `Info()` 返回 `Plaintext=true`，UI 明确显示“明文存储，未加密”，不把同文件保存伪装成加密。
- 目录强制 0700、文件 0600；写入使用同目录 0600 临时文件 + `fsync` + `rename`；拒绝已存在的符号链接（文件与存储根），并限制单值 64 KiB、单个文档 4 MiB。
- 值不进入项目目录、项目 YAML、普通变量或导出；测试逐文件扫描 `.gorequest/` 断言无泄漏。

### 2.2 持久偏好与管理清单

- `preferences.json` 按 scope 保存 `keychain`/`file`，重启后 `openProject` 读取并构建对应 provider。
- `manifest.json` 按 scope 记录用户通过 GoRequest 写入过的名称（不含值）。Keychain 不能枚举，清单使“未在项目中声明但已管理”的名称在切换时仍可找回。
- 旧版本已经写入但既未声明、也未进入清单的 Keychain 条目无法枚举；计划会明确显示“来源后端无法枚举全部条目，只覆盖项目声明与已管理清单”，不声称迁移全库。
- 环境变量 `GOREQUEST_SECRET_<NAME>` 保持只读覆盖；切换不把它当作可写迁移目标。

### 2.3 切换事务

- `BuildSecretSwitchPlan` 先枚举“项目声明 ∪ 管理清单 ∪ 来源可枚举项 ∪ 目标可枚举项”，预读来源与目标，生成不含值的逐项计划。
- 目标已有不同值时标记冲突；默认 `ConflictKeepTarget`（保留目标），用户必须显式选择“覆盖目标值”才会替换。
- `ExecuteSecretSwitch` 重新读取来源最新值，逐项 `Set` 后 `Get` 读回校验；任何失败按逆序恢复目标原值/删除本轮新建项，来源永不删除。
- 只有全部复制与校验成功后才 `SetSelectedKind` 持久化选择；若偏好写入或 provider 刷新失败，同样回滚目标写入并恢复旧偏好。
- `Manager.refreshSecretBackend` 重建同 scope 所有窗口的 `ps.secrets`/`secretBackend`，清空管理页、环境编辑器、单 secret 弹窗和鉴权诊断缓存。HTTP、WS、Runner 与 Mock 均通过 `ps.secrets`/`secretsProvider` 读取新后端，不是只改 UI 标签。

### 2.4 UI 与可访问性

- 凭据页新增“秘密与存储”区：当前后端、实际路径/服务、明文警告、不可用原因、Env 只读说明；目标选择沿用 `uikit.Select`（窗口内 popup、键盘/焦点/边缘翻转由现有组件处理）。
- 切换计划行显示每个 `{{secret.name}}` 的“将复制/相同/冲突/仅目标/两边未设置”状态；冲突时提供“保留目标值/覆盖目标值”两个明确动作，未选择覆盖时确认按钮不会覆盖。
- 单 secret 弹窗显示同一后端信息与“更改存储位置”入口；环境编辑器密钥状态回退后端改为当前选中后端。
- 文案更新了“仅写入系统凭据”“系统凭据不可用时失败”等旧说法，改为“当前所选存储位置”与“不会静默降级”。
- 按 `ui-ux-pro-max` 核对：状态不只靠颜色（文字+颜色）、明文/不可用用 warning/danger 语义色、按钮有可读 label、选择器与计划在现有 modal 滚动区内不越界、未引入新动画或破坏现有焦点。

### 2.5 可用性探测

- Keychain 的 `Info()` 不探测；`Probe()` 只在用户打开存储区、打开单 secret 弹窗或开始切换时读取一个哨兵键（不写、不读真实 secret），并缓存结果供 `Info()` 显示。
- 不支持/锁定/其他错误会显示具体原因；文件后端 `Probe()` 只做根目录 `Lstat`，不创建文件。

### 3.2 新增覆盖

- 双向切换：Keychain → 文件 → Keychain；切回重新读取文件最新值并写回 Keychain。
- 重启：同一 config/secret root 的第二个 Manager 打开同一项目后仍选择文件后端并能读到值。
- 多窗口：窗口 A 切换不影响窗口 B 的后端、provider 与值。
- 冲突：默认保留目标值；显式覆盖后目标值被来源值替换。
- 中途失败：平台层注入第二个名称写入失败，验证已写目标项回滚、目标原有值恢复、来源不变；成功后的 undo 日志可恢复目标。
- 不可用：目标根为符号链接时计划显示不可用、确认被禁用/控制器失败、旧后端与值保持；Keychain 探测 `ErrUnsupported` 时 `Info()` 显示原因且无写入。
- 引用名与清单：项目声明的 `apiToken` 与未声明的 `undeclaredSecret` 均被切换复制；环境文件仍只有名称；清单持久保存两者。
- 真实执行路径：切换后用 `buildTrackedTabPlan` + `core.Execute` 向 loopback `httptest` 发送 `Bearer {{secret.apiToken}}`，服务端收到文件后端/切回后 Keychain 的最新值。
- UI：headless 渲染断言单 secret 弹窗显示实际文件路径、明文警告与“更改存储位置”；凭据页显示存储区、计划与确认，并完成一次真实切换。

## 4. 限制与未验收

- **未启动真实桌面窗口**，未做 macOS/Windows/Linux 实机点击、真实 Keychain 锁定/解锁弹窗、系统凭据权限提示、真实文件系统 ACL 或辅助功能验收；不把 headless 结果冒称实机验收。
- 自动化测试只使用 fake driver 与临时 home/临时 secret root，不读写、不迁移、不清理用户真实 Keychain 或真实 `~/.gorequest`。
- 旧版本已写入但未声明、且未进入新管理清单的 Keychain 条目无法枚举；切换计划会明确声明覆盖边界，不声称全库迁移。新写入的名称从本版本起进入清单。
- 文件后端为**明文**，仅依赖 0700/0600 与文件系统权限；Windows 上 Go 的 `Chmod` 只部分映射 ACL，跨平台权限行为未实机验证。
- 不承诺持续双写：切换只复制当时的最新值；来源副本保留，之后再次切换会重新复制当前值。
- 文件后端的读-改-写只在进程内串行；未实现跨进程文件锁，多个 GoRequest 进程同时写同一 scope 的极端情况未覆盖。
- Keychain 探测在用户显式打开存储区/弹窗/开始切换时读取一个哨兵键；若系统在锁定时弹出解锁提示，属于该显式动作的预期交互，未实机验证。
- 未修改 U19 的 `uikit.Select` 或 U20 的欢迎窗口；本卡不需要 `U18-integration.patch`。
