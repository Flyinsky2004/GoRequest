## 2. 实现与接线

### 2.1 语言判断修正

`interopMsg()` 原实现为 `a.mgr.cfg.language() == "zh"`，而配置语言常量是 `zh-CN`/`en`，因此中文目录从未生效，导入/导出菜单与弹窗一直显示英文。现改为 `a.interopLanguage() == langEnglish` 选取英文，否则中文；每帧读取配置，切换语言后下一帧即生效。

### 2.2 摘要

`displayImportSummary` 在中文下按 Core 现有稳定模板重写 cURL、Postman Collection/Environment、Portable Bundle、OpenAPI/Swagger 路由与校验摘要，保留方法、脱敏 URL、版本、名称、计数等动态值；无法识别的模板回退为基于 `Format` 与 `Changes/Losses/Conflicts` 计数的中文结构化摘要，不再输出整句英文。

### 2.3 变化、映射、变量与损失

- 文件变更：`[新建/更新/删除/移动] 相对路径（N 字节）`，路径与字节数为原始技术事实。
- ID 映射：本地化实体类型、动作与 `[已重命名]`，`SourceID/TargetID/TargetPath` 原样保留。
- 变量：本地化 `变量/Secret` 与来源（Postman 环境/集合、cURL 鉴权/请求头、便携包），名称、`{{ref}}`、脱敏预览原样保留。
- 本地文件槽位：`[本地文件槽位] local:<slot>（发送前请绑定本地文件）`。
- 损失/告警：`[严重度 / 稳定code] 本地化消息`；严重度覆盖提示/警告/不支持/安全脱敏/已阻止，code 始终保留。
- 冲突：本地化 `request/folder/environment/auth/doc/asset/attachment` 与 `already exists at`、唯一 ID 分配失败等模板。

损失消息按 `LossItem.Code` 查表并用正则提取英文消息中的动态值（名称、槽位、路径、行数、脱敏掩码等），覆盖 cURL、Postman、便携包与 OpenAPI 路由/同步诊断。未知 code 或提取失败时输出 `未收录的转换诊断：<原始详情>`，保留原技术细节。

### 2.4 错误

已知桌面错误整句翻译（空 cURL、空文件、未预览、无回滚记录、未选请求、空导出路径、目标已存在等）；已知 Core 前缀（`Read import file:`、`parse Postman Collection structure:`、`parse Postman Environment structure:`、`import plan cannot be applied:`、OpenAPI A03 路由等）翻译分类并保留后续技术细节；其它错误输出 `导入失败：<原文>` / `导出失败：<原文>`。已本地化的脏缓冲错误不会被二次包裹。

### 2.5 安全边界

- 未改 Core 脱敏逻辑；预览仍使用 `Redactor` 后的 `Summary/LossItem.Message`，测试断言原始 Bearer token、Cookie 值不出现。
- 导出预览仍是脱敏 cURL/清单，未新增 raw cURL 输出。
- 技术 code、JSON/YAML 键、路径、ID、变量引用与请求数据不翻译。
