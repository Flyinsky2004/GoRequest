## 问题与真实原因

现象：发送完成后，地址框（请求行 URL 输入）总是红色，成功响应也一样。

原因不是 URL 被标记为 invalid，而是 MyGo `TextInput` 的焦点描边：

1. `mygo@v0.7.4/ui/textinput.go:22` 给 `TextInput` 安装
   `e.styleFn = func(e *node) { inputBorder(t, e, e) }`。
2. `mygo@v0.7.4/ui/form.go:301` 的 `inputBorder` 在输入框获得焦点时把
   `box.borderC` 设为 `t.Accent`（invalid 才用 `t.Danger`）。
3. `internal/desktop/uikit/palette.go` 的 `Theme()` 把 `t.Accent` 设为
   `p.Accent`：浅色 `ui.Oklch(0.6, 0.21, 24)`、深色
   `ui.Oklch(0.66, 0.2, 22)`，色相约 22–24°，是明显的红橙色。
4. `internal/desktop/app.go:357-358` 在每次发送结束（成功、失败、取消）后都设置
   `tab.focusURL = true`；`workspace.go` 下一帧调用 `inp.Focus()`。

因此发送后 URL 输入必然处于焦点，MyGo 每帧把它自己的 1px 边框重新涂成红橙色
Accent。外层的 `urlGroup` 边框虽然仍是 `p.Hairline`，但内部输入框的描边才是用户
看到的“地址框红色”。这不是 `t.Danger` 的 invalid 路径。

## 实现

只改 `urlGroup` 及新增的专属状态模块，没有改 `body_http_ui.go`、
`request_form.go`、`response_view.go`、`internal/core`、`go.mod/go.sum`、框架或全局设置；
不需要改 `app.go` / `tab.go`，状态完全由 Tab 已有的 `Sending` / `Resp` / `RespErr` 推导。

- `internal/desktop/workspace.go`（仅 `urlGroup`）
  - 请求行圆角组自己持有唯一边框，颜色由 `urlStatusBorderColor(urlSendStateOf(tab), p)` 决定。
  - URL 输入改用 `ui.TextInputBase`：保留编辑、选区、快捷键、`focusURL` 行为，
    但不再有 MyGo 自带的 focus/invalid 边框和 `styleFn`。
  - 用一个普通 `ui.Row` 承载原来的 URL 外观（`p.Sidebar` 背景、6/10 内边距、
    radius 8），视觉上仍是方法段 + 分隔线 + URL 输入。
  - 焦点可见性由组级 `DrawOver` 单独绘制：URL 输入有焦点时画 2px 中性
    `p.Muted` 圆角环（radius 12）。刻意不用主题 accent 焦点色，避免成功绿边框外
    再出现一圈红橙色被误读为错误。
- `internal/desktop/url_status.go`（新增）
  - `urlSendState` / `urlSendStateOf`：从 Tab 现有字段分类发送结果。
  - `urlStatusBorderColor`：复用现有 palette，不新增颜色 token。

状态映射：

| Tab 状态 | 边框颜色 | 说明 |
| --- | --- | --- |
| 空闲（未发送） | `p.Hairline` | 与原组边框一致 |
| `Sending` | `p.Muted` | 中性，避免与失败红混淆；优先于上一次结果 |
| 成功（HTTP < 400） | `uikit.MethodColor("GET", p)` | 现有成功绿 |
| HTTP 失败（>= 400） | `uikit.MethodColor("DELETE", p)` | 现有失败红 |
| 超时 / DNS / 连接 / TLS 错误 | `uikit.MethodColor("DELETE", p)` | 统一失败红 |
| 用户取消（`isCanceledErr`） | `p.Muted` | 终态但中性 |
