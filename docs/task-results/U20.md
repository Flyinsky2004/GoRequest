## 2. 实现与接线

### 2.1 真正生效的高度

原问题不是单个常量：`newProjectGeometryFor` 取 `winH - 80`（40 DIP 模态外边距 + 上下各 20 DIP 面板内边距），再受 `newProjectMaxHeight` 限制。旧默认窗口 480 高时，面板实际只有 `min(480-80, 460) = 400`，只改 max 常量仍是 400。

本次同时调整两处：

- `manager.showWelcome` 默认窗口高度 `480 → 640`：默认面板高度变为 `min(640-80, 600) = 560`。
- `newProjectMaxHeight 460 → 600`：用户放大欢迎窗口时面板可继续增高到 600，而不是停在 460。

`MinWidth/MinHeight` 仍为 `560/360`，短屏窗口尺寸上限与滚动行为不变；未新增任何窗口动态 resize 调用，因此不依赖 MyGo 未公开 API，也不影响 `manager.openProject` 使用 `cfg.windowSize()` 恢复已有项目窗口尺寸。

### 2.2 布局与间距

- 面板外层（标题/提示/滚动体/底部操作）与滚动内容列间距由 10 提升到 12 DIP，符合 `ui-ux-pro-max` 的 4pt 间距体系与 `whitespace-balance`。
- 保留左右两大模式卡（`Independent project` / `Alongside existing code`）并排、名称/位置字段、最终路径预览、键盘提示与底部 `Cancel`/`Create`。
- 滚动体 `Grow(1)`、底部操作行 `Shrink(0)` 的结构不变：短屏只滚正文，`Cancel`/`Create` 始终固定可见；`Escape` 关闭与键盘焦点行为未改。
- 按 `ui-ux-pro-max` 核对：可见标签、单一主操作（Create）、错误/提示文字贴近字段、焦点不被底部遮挡（`focus-not-obscured`）、模态保留取消出口（`escape-routes`）、大字体下靠滚动而非裁切（`dynamic-type`）。

### 2.3 headless 实测几何

同一 view 在 `ui.Tester` 中测得：

| 窗口 | 面板高 | 键盘提示行高 | 正文末行到 footer 间距 |
| --- | --- | --- | --- |
| 720×480（旧默认） | 400 | 8.23（被滚动视口裁切，完整一行 12.96） | 19.0 |
| 720×640（新默认） | 560 | 12.96 | 174.3 |
| 900×760（放大） | 600 | 12.96 | 214.3 |
| 900×1200（超高） | 600（封顶） | 12.96 | 214.3 |
| 560×360（最小） | 280 | 正文滚动 | footer 固定，Cancel 可点 |
