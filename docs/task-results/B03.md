## 1. 实际完成范围

### 1.1 纯 Go Core 层（`internal/core/`）
1. **自定义 HTTP 方法校验（`internal/core/body.go`）**
   - 新增 `StandardHTTPMethods` 与 `ValidateHTTPMethod(method string) error`，按 RFC 9110 §9.1 Token（`tchar`）规则校验任意合法自定义方法（如 `PURGE`、`PROPFIND`、`REPORT`、`QUERY`、`MKCOL`、`LOCK`），拒绝空白字符、控制字符与非法分隔符。
2. **类型化复杂 Body 模型与兼容 AST 往返（`internal/core/body.go`、`internal/core/bodyhelp.go`）**
   - 在**不修改公共文件 `internal/core/model.go`** 的前提下，基于现有 `core.Body{Type, Value *yaml.Node, File}` 构建 `TypedBody`、`FormField`、`MultipartPart`、`FileRef`、`InspectBody`、`(*TypedBody).ToBody` 与 `ValidateBody`。
   - 支持模式：`none`、`json`、`text`、`xml`、`urlencoded`（兼容别名 `x-www-form-urlencoded` / `form-urlencoded`）、`form-data`（兼容别名 `multipart` / `multipart/form-data`）、`binary`。
   - **JSON 键序与往返保真**：重写 `BodyEditText` 采用递归保留 YAML Mapping 顺序的 JSON 格式化，避免 `map[string]any` 打乱键序；拒绝重复映射键。
   - **防静默吞字段 / 防吞未知模式**：
     - 未支持模式（如 `type: graphql`）识别为 `BodyUnsupported`，`CloneBody` / `BodyPreviewYAML` 完整保留原始 `*yaml.Node` AST。
     - `urlencoded` 条目、`form-data` 分片及 `binary` 映射中的未知扩展键全部收集到 `Extra []*yaml.Node`，保存时原样写回磁盘，执行/校验（`ValidateBody` / `BuildBody`）时显式返回 `*core.ConfigError` 拒绝含糊发网。
3. **复杂 Body 编码引擎与 Multipart Boundary 托管（`internal/core/body_encode.go`、`internal/core/plan.go`）**
   - 实现 `BuildBody`、`EncodeURLEncodedFields`、`OpenBodyStream` 与 `BuildPlanWithOptions`；`internal/core/plan.go` 仅替换 `BuildPlan` 内第 154–197 行的 Body 构造区委托给 `BuildBody`，未触碰 `Execute`/transport、Auth 或响应处理。
   - `urlencoded`：严格保持切片顺序、重复键、空值（`empty=`）、`enabled: false` 过滤，支持 `encoded: true` 预编码标记与 `{{variable}}` / `{{secret.name}}` 模板解析，杜绝二次百分号编码。
   - `form-data` / `multipart`：由引擎通过 `mime/multipart.Writer` 每次生成随机 boundary，并以 `ForceContentType: true` 强制覆盖用户手写或缺失 boundary 的 `Content-Type` 请求头；支持文本项与文件项混合、可选覆盖 `fileName` 与 part 级 `contentType`（默认按扩展名推断或回退 `application/octet-stream`），严格拦截 CRLF 头注入。
   - `binary`：支持 `application/octet-stream` 默认类型及模板化 `contentType` 覆盖。
4. **`body.file` 安全边界、本机文件映射、大小上限与取消（`internal/core/body_files.go`）**
   - `DirFileOpener`（项目相对文件端口）：词法层拒绝空路径、绝对路径、反斜杠、Windows 盘符、`..` 穿越与隐藏 `.git` 路径；文件系统层对 `.gorequest/` 根目录与目标文件同时执行 `filepath.EvalSymlinks` 真实路径包含校验，拦截软链文件逃逸、软链父目录逃逸、悬空软链、目录与 FIFO/设备非常规文件。
   - `LocalFileProvider` / `MapLocalFiles`（显式本机文件映射端口）：解析 `local:<slot>` 或分片 `localFile: <slot>`，未绑定槽位或目标文件缺失一律在发网前返回 `*core.ConfigError`（0 次网络请求）。
   - 上传保护：默认单请求总上传上限 `DefaultMaxUploadBytes = 64 MiB`（可通过 `PlanOptions.MaxUploadBytes` 配置）；文件读取按 32 KiB 分块检查 `ctx.Done()` 与累计字节数，支持即刻取消以及流式读取端口 `OpenBodyStream`（`boundedCancelReadCloser`）。
5. **URL / 模板变量安全预览与原始参数解析（`internal/core/body_url.go`）**
   - `PreviewTemplateVars`、`PreviewRequestURL`、`PreviewURLEncodedBody`：内置 `maskingSecretProvider` 将已绑定秘密统一遮罩为 `(secret)`，绝不在预览结构中暴露真实秘密值；识别未定义变量、循环引用与未绑定秘密；保持已有 URL Query 与表单 Query 拼接时不发生二次编码。
   - `FormatRawQueryKV` / `ParseRawQueryKV`、`FormatRawURLEncodedFields` / `ParseRawURLEncodedFields`、`FormatFormBatchLines` / `ParseFormBatchLines`：支持带前导 `?` 的原始编码串与 `# ` 禁用行往返，单次解码字面量百分号转义同时保留 `{{...}}` 占位符。

### 1.2 MyGo Native UI 桌面层（`internal/desktop/`）
1. **专属原生 Body 编辑器（`body_editor.go`、`body_state.go`、`workspace.go` 的 `bodyEditor`、`tab.go` 的 Body 区）**
   - 支持 `None` / `JSON` / `XML` / `Text` / `Form URL-Encoded` / `Multipart` / `Binary` 七种模式切换。
   - `JSON` / `XML` / `Text` 支持 `Inline`（语法高亮代码编辑器 + 底部秘密遮罩变量预览）、`Project File`（自动补全 `.gorequest/` 内附件路径 + 实时文件就绪/错误状态）、`Local Mapping`（槽位键 + 本机路径 + 原生文件选择器 `Choose File…` + `Unbind`）。
   - `Form URL-Encoded` 支持 `Key:Value` 表格（含 `Enabled`、`Pre-encoded` 勾选、行删除、尾部幽灵行）、`Batch Lines`、`Raw Encoded` 三态切换及底部实时编码预览（秘密遮罩）。

   - `Binary` 支持 `Project File` / `Local Mapping` 切换与可选 `Content-Type` 覆盖。
   - **未支持模式与未知字段保护 UI**：遇到 `graphql` 等未支持 Body 模式时展示红色保留卡片、只读原始 YAML 预览及显式 `Replace Body` 按钮；遇到未知扩展字段时显示警告横幅，保存其他修改绝不吞掉原数据。

## 2. 存储格式候选扩展与兼容方案（v1 草案说明）

> **重要声明**：根据 `docs/storage-format.md` 与任务约束，`schemaVersion: 1` 目前仍处于 **v1 草案（Draft）阶段，尚未冻结**。以下 B03 新增表达均为在现有 `core.Body{Type, Value, File}` YAML 契约上的向后兼容候选方案，**未宣称格式冻结**。

1. **向后兼容既有格式**：
   - `none`（省略 `body` 或 `type: none`）、`json`（`value` 为 YAML/JSON 节点）、`text` / `xml`（`value` 为字符串）保持与既有 `.request.yaml` 100% 兼容。
2. **文件引用与显式本机映射（候选草案）**：
   - 项目内相对文件：`body.file: assets/payload.bin`（必须位于 `.gorequest/` 内，禁止 `..` 与软链逃逸）。
   - 显式本机文件映射：顶层 `body.file: local:<slot>`（例如 `file: local:avatar-file`），或 `form-data` 分片内 `localFile: <slot>`（同时兼容 `file: local:<slot>`）。共享 YAML 仅记录逻辑槽位名 `<slot>`，真实本机绝对路径只存当前设备配置目录 `local-files.json`。
3. **复杂 Body 模式（候选草案）**：
   - `urlencoded`：`type: urlencoded`，`value` 为有序序列 `[{name, value, enabled?, encoded?}]`（同时兼容读取标量字符串与 `file`）。
   - `form-data`：`type: form-data`（兼容读取别名 `multipart`），`value` 为有序序列 `[{name, kind: text|file, value?, file?, localFile?, fileName?, contentType?, enabled?}]`。
   - `binary`：`type: binary`，`file: <relPath | local:slot>`，可选 `value: {contentType: image/png}`。
4. **向前兼容与未知项保留规则**：
   - 未知 `body.type` 在加载与保存无关编辑时原样保留整个 `body` YAML 子树；未知分片/条目字段保存在 `Extra` 节点中原样写回，仅在实际发网构造 `Plan` 或执行校验时显式报错。
