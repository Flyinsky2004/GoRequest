## 5. 实际实现

### 5.1 `internal/mockserver/suite_lifecycle.go`（最小扩展）

- `SuiteMockConfig` 新增 `Redactor *core.Redactor`；`StartForSuite` 在 `NewServer` 时传入，服务在 `Start` 前即完成脱敏器注册，不存在“先监听后脱敏”窗口。`RunSuiteWithControlledMock` 同步改为启动前构建并传入 Redactor。
- 导出 `InjectSuiteVariables(suite, injected)`（原私有 clone 的导出包装），注入只改副本，不改调用方 Suite/项目。
- 新增 `SuiteMockLease` + `StartSuiteMockLease(ctx, project, cfg)`：返回注入变量、实际 `BaseURL/BoundAddr/Port`、场景、快照摘要、受限脱敏访问记录、`ServerStopped`；`Stop` 用 `sync.Once` + mutex，幂等、可并发，只有首次调用执行关闭，失败不会被报成已停止。
- 兼容性：原有 `RunSuiteWithControlledMock`/`StartForSuite` 签名与行为保留；只把 Redactor 从“启动后 SetRedactor”改为“启动前注入”，并复用导出的注入 helper。

### 5.2 `internal/desktop/runner.go`（最小改动）

- `runnerState` 增加本次运行的纯值配置 `mockEnabled/mockScenario/mockPort/mockEndpointVar/mockScenarios` 与结果 `mockResult`；创建时默认关闭、端口 `0`、场景 `default`、端点变量 `mockUrl`。
- `OpenRunner` 读取项目规则场景（`CompileProjectMocks`，有界：1 MiB/文件、512 规则），失败回退内置场景；不启动监听。
- `StartRunner` 在 `prepareDesktopRunner` 之前：校验配置 → 编译冻结 `CompiledSnapshot` → `StartSuiteMockLease` 绑定回环（0/合法端口）→ 用实际地址注入 Suite 副本 → 再走原 `prepareDesktopRunner`（签名不变、非 Mock 行为不变）。Prepare 返回错误时立即有界 `Stop` 并记录真实 `ServerStopped`。
- worker 与 Mock 共用 run context；ctx 取消时 watcher 立即停服务；`defer` 有界 stop 作为安全网（含 panic 路径）；成功/断言失败/配置失败/网络错误/取消都回收。结果仍走既有 mailbox/generation/weak owner/`Window.Update`，旧 generation 不会覆盖新结果或取消新 Mock。
- 结果元数据（实际端口、场景、规则摘要、是否释放、受限访问记录数）只存在内存 `runnerState.mockResult`，不写共享 YAML；JSON/JUnit 导出逻辑未改。

### 6.1 成功 / 失败 / 取消 / 隔离证据

- 两步两行 Suite（2 行 × 2 步 = 4 请求）真实 loopback Mock：`passed`，`Summary.Rows=2/StepsTotal=4/Passed=4`；`mockResult` 报告实际 `http://127.0.0.1:<port>`、场景 `default`、非空规则摘要、`ServerStopped=true`、4 条访问记录且均匹配 `get-item`；运行后端口可重新 `net.Listen`；共享 mock/env 文件字节不变。
- 冻结：`StartRunner` 返回后改写 mock 规则为 500，本次仍 `passed`（用冻结 200），下一次 `failed`（看到新 500）；改动 `mgr.secrets` 后本次仍用旧 Secret（200），下一次用新 Secret（500）。
- 取消：5s 延迟规则运行中 `CancelRunner`，4s 内返回 `canceled`，`ServerStopped=true`，端口释放。
- 窗口关闭：触发已注册 `OnClosed` 后 run context 取消，监听端口在限定时间内释放（窗口状态按既有语义删除，结果不再投递）。
- Prepare 失败：本地文件上传 body 使 `prepareDesktopRunner` 返回错误；lease 立即释放，`config_error`，端口释放。
- 端口冲突：占用固定端口后启动得到 `config_error` 且 notice 含 port conflict，无 lease 残留，外部监听未受影响。
- 坏规则 / 未知场景：均 `config_error`，不进入 worker。
- 两项目并发：各自独立端口/记录；取消项目 0 不影响项目 1（0 为 canceled，1 为 passed），两者都释放。
- 取消后重跑：generation 仅在真正新运行时递增；重跑使用新规则并 `passed`，旧回调不覆盖。
- 脱敏：访问记录与 JSON/JUnit 报告均不含 fake Secret 明文；Mock 访问记录由服务在接收首请求前注册的 Redactor 脱敏。
