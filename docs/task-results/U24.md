## 1. 审计结论（实现前）

静态链路确认：`ExecuteWithOptions` 对普通响应调用 `readAndDecodeResponseBody` → `readBoundedChunks` 读完整 Body 后才构造 `ExecResult`；桌面 `App.send` 在 `core.Execute` 返回后一次性 `win.Update` 写入 `tab.Resp`。因此服务端即使已 flush 首个 SSE 事件，响应区也要等连接 EOF（或超时/取消）才更新，**没有实时 UI**。本轮不是只写审计，已落实下面的增量实现与真实接线。

## 3. 实现与接线

### 3.1 Core：增量解析与保留

- `Content-Type: text/event-stream`（含 `charset` 等参数，大小写/空白容错）自动进入流式路径；`ExecuteOptions.Stream` 为 nil 的调用方仍走原完整读取，普通 HTTP 与 Runner/OAuth 等路径不变。
- 解析 `event`/`id`/`retry`/多行 `data`/注释，支持 LF、CRLF、CR 以及 `\r`+`\n` 跨 chunk；按字节缓冲完整行，UTF-8 多字节序列跨 chunk 不拆分。`id` 按 EventSource 规则持久；EOF 时保留已收到的未闭合事件（调试工具不丢内容）。
- 边界：单行 `MaxSSELineBytes`（256 KiB+64）、单事件 `MaxSSEEventBytes`（256 KiB）、注释条数、正文沿用 `MaxResponseBytes`（默认 32 MiB）；超限截断/丢弃并标记，不无界增长。
- 每个事件在回调前用 `Redactor` 脱敏 `id/type/data/comments`；最终 `ExecResult.Body` 也脱敏。历史记录仍走既有 `localstate` 脱敏。
- 流结束分 `open/completed/canceled/timeout/failed`；取消、显式超时、连接中断都返回**非 nil 的 `ExecResult` + 已收到正文**，同时返回 `RunError` 供状态栏/历史分类。
- 超时语义：显式请求 timeout 或设备 `TotalTimeout` 继续生效；内置 10s 默认值在确认是 SSE 后停止计时，避免健康长连接被默认值切断。非 SSE 仍按原默认超时执行。

### 3.2 Desktop：实时显示与隔离

- `App.send` 为每次发送创建 `tabSSEStream` 并挂到 `plan.Network.Stream`；新发送先取消旧请求并关闭旧流，`sendSeq` 作为 generation，旧完成回调/旧 flush 都不能写入新响应。
- 读 goroutine 只把事件追加到互斥 pending 列表；`scheduled` 标志保证同一时刻最多一个 `win.Update`，事件突发合并为一帧。pending 超过 8 MiB 时读 goroutine 等待 UI 消费，形成真实背压。
- UI 线程把已脱敏事件重建成熟悉的 `event:/id:/retry:/data:` 文本，写入 `tab.Resp.Body` 并原地 `Buffer.Reset`，保留滚动位置；复制/保存/历史都使用同一份脱敏文本。若服务端把非 SSE 内容标成 `text/event-stream`（例如 JSON 错误页），解析器没有事件时回退显示已脱敏的原始正文，不显示空响应。
- 状态区分：连接中显示 `Sending…`；已连接显示 `SSE 接收中 · N 个事件`（尚无事件时正文显示等待提示）；完成后显示状态码 + `SSE 完成 · N 个事件`；取消/超时/断流显示对应“已保留 N 个事件”状态与一行说明，并保留正文、提供重试。
- 关闭 tab、关闭窗口、新发送都会 `cancel` 请求并解绑流；`cancelAllRequests`/`removeTab` 已接入。

## 5. 限制与未验收

- 未启动真实 MyGo 桌面窗口；`ui.Tester`/headless 窗口与 loopback HTTP 不等于实机窗口、输入法、系统缩放、亮暗主题与视觉验收。
- 未对真实公网 SSE 服务、企业代理、mTLS、系统代理做端到端验证；这些路径复用既有 `ExecuteOptions`，但本轮只以本地 `httptest` 覆盖。
- 未实现 EventSource 的自动重连/`Last-Event-ID` 续传；本轮是请求-响应式实时查看，取消/断流后由用户显式重试。`retry` 仅解析并展示。
- 未在真实压缩 SSE 上做长跑；gzip/deflate 增量解压复用既有判定，只有本地小样本覆盖。
- 事件/正文缓冲有上限（单事件 256 KiB、正文 32 MiB、pending 8 MiB），超限会截断并明确提示，不保证完整保存超长流。
- 每帧把累计事件文本写入只读编辑器是 O(n) 复制；本轮优先保证正确性与“合并通知”，未做增量 rope 追加优化。接近 32 MiB 的超大流会有明显渲染开销。
- 未改 WebSocket 引擎；WS 行为不在本轮范围。
