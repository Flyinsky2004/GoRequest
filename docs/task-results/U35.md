## 实现摘要
1. **`internal/desktop/quit_guard.go`（更新交接与逐窗口未保存守卫）**
   - `installerHandoff` 挂在 `Manager.handoff`，在更新包下载并完成 SHA-256 校验后，通过 `handOffInstaller` 在 UI 线程进入交接流程。
   - **逐窗口内容指纹批准（不提前 `clearDirty`）**：
     - 更新交接中用户选择“保存”仍走 `saveAllDirty()`（失败则保持守卫弹窗并显示错误，不打开安装包、不退出）。
     - 更新交接中用户选择“放弃”（discard）时，**不提前调用 `clearDirty()`**，而是通过 `approveWindow` 记录该窗口当前各 dirty tab（请求草稿字段/KV/Body、文档 `DocEditor.Buffer`）与 `envUI.signature()` 的内容指纹。
     - `promptQuitGuard` 在更新交接分支跳过已批准且指纹未变的窗口；若下载期间或后续窗口守卫期间某窗口产生新编辑（内容变更或新 dirty tab/env），指纹失配会重新弹窗确认。
     - 若后续窗口点击“取消”或安装器启动失败（`h.launch()` 返回错误），直接丢弃 `handoff` 及其批准集，前面窗口原有的 `Dirty` 标记与内存草稿天然完整保留，后续关闭窗口或普通退出仍会触发未保存提示。
     - 仅当所有窗口均已保存或按当前指纹批准、且 `h.launch()` 成功启动安装器后，才对已批准放弃的窗口执行 `clearDirty()`，记录 `ResultDownloaded`，并置 `m.quitting = true` 调用 `m.quit()`（默认 `mygo.App.Quit()`）走正常生命周期退出。
   - **取消与普通退出隔离**：
     - `abandonHandoff` / `reconcileHandoff` 及 `promptQuitGuard` 入口检查 `m.handoff != nil && !m.pendingQuit`，确保取消更新后下次普通退出绝不会意外启动安装器。
     - 提供 `tryResolveHandoffGuard(app *App, discard bool) bool` 供 `app.go` 的 `resolveCloseGuard` 最前调用；同时在 `onQuitGuardSettled` 内保留 `settleCompat` 兼容回退，使 `app.go` 补丁合入前后均能保持 `Dirty` 不丢失。
2. **`internal/desktop/manager.go`、`update_controller.go`、`update_ui.go`、`update_i18n.go`**
   - `Manager` 接入 `handoff *installerHandoff` 与可注入的 `quitApp func()`。
   - 更新 `ReadyMac` / `ReadyWindows` 文案（说明已打开安装器且 GoRequest 即将退出，macOS 仍提示拖入“应用程序”完成替换，不谎称已安装），新增 `HandoffCanceledTitle` / `HandoffCanceledBody` 文案。
3. **`internal/desktop/quit_guard_test.go` & `update_test.go`**
   - 使用 fake installer / fake quit 与临时项目目录验证调用顺序（`open,quit`）、干净窗口、脏窗口保存、脏窗口放弃、取消、取消后普通退出不启动安装器、保存失败阻断、安装器启动失败不退出、**放弃后安装器启动失败保留 `Dirty` 与内存草稿**、**多窗口先放弃后取消保留第一窗口 `Dirty` 与内存草稿**、多窗口逐个提示、下载期间新增编辑、守卫期间对已保存或已放弃窗口再编辑重检、下载取消、交接期间用户主动退出。
   - 包含主代理复现回归 `TestReviewHandoffDiscardThenCancelKeepsDirty` 与 `TestReviewHandoffDiscardThenLaunchFailureKeepsDirty`。
