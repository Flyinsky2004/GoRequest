## 2. 实现内容

### 2.1 新 `internal/update` 包

- `version.go`：SemVer 2.0.0 解析与比较，支持 `v` 前缀、`-dev`/`-beta.1` 预发布、`+build`；无版本或非 SemVer 值明确归为开发版本，不参与比较。
- `release.go`：只读公开 GitHub Releases API（固定 `Flyinsky2004/GoRequest`，`https://api.github.com/repos/Flyinsky2004/GoRequest/releases`）。
  - 分页最多 3 页 × 100 条；跳过 draft；预发布只提供给预发布通道；只接受严格高于当前版本的候选，按 SemVer 取最高可用版本，不取列表第一项、不降级。
  - 按 `GOOS/GOARCH` 选择实际附件：macOS `.dmg`、Windows setup `.exe`；排除 SHA256SUMS；无对应附件返回 `no-asset`，不把 zip 当安装器。
  - 分类错误：网络、限流、无 Release、HTTP、无附件、校验、下载；`errors.Is(context.Canceled)` 可穿透。
  - 响应体有上限（API 2 MiB、校验文件 1 MiB），Release notes 按 rune 截断到 4000。
- `download.go`：下载到独立临时目录（0600），边写边算 SHA-256；优先 GitHub asset `digest`，否则下载 `SHA256SUMS` 并按 basename 匹配；缺校验值直接失败；大小上限默认 1 GiB；取消时删除半成品。`OpenInstaller` 在 macOS 用 `open` 打开 dmg、Windows 启动 setup exe，不退出当前应用。
- `state.go`：持久状态 `<config dir>/GoRequest/update-state.json`（0600，原子写，内存缓存避免每帧读盘）。字段含本地日期、检查时的安装版本、上次结果/错误、最新版本、跳过版本、暂不更新版本+日期、`neverNotify`、`autoCheck`。无配置目录时仅内存保存，运行期仍生效。

### 2.2 Manager 与窗口接线

- `Manager` 新增 `update *updateController`；`NewManager` 装配真实 HTTP/状态存储，测试用 Manager 字面量保持 `nil`，不会触网。
- `Manager.Start` 用 `defer` 在启动窗口建立后异步触发自动检查（20s 超时），离线/限流/无 Release 不阻塞启动。
- 自动检查：Manager 级、每个“本地日期 + 安装版本”最多一次；安装版本变化立即失效，同日安装 V2 后仍能查到 V3。
- 手动检查：忽略本日缓存、skip、Later、neverNotify，始终执行并显示结果；若自动检查正在运行，手动请求排队，结束后补一次手动结果。
- 弹窗宿主窗口：优先可见的欢迎窗口，否则第一个项目窗口；打开项目/回到欢迎时转移宿主，避免弹窗落在隐藏窗口。只有宿主窗口渲染，多个窗口不会重复显示。
- `App.View` 与 `welcome.View` 末尾接线 `updateModalFor`；未改 `App.trySend`/HTTP/Tab/response 区域。

### 2.3 更新弹窗与设置

- 弹窗四动作：暂不更新（本日同版本不再自动提示）、更新（下载/校验/打开安装器）、跳过此版本（只针对该版本）、永远不提示（持久关闭自动检查/提醒）。另有“设置”入口。
- 显示当前版本、目标版本、Release notes；检查中/下载中/结果状态均双语；Esc/外点可关闭，检查或下载中关闭会取消任务。
- “更新”成功后明确说明：文件已按发布方 SHA-256 校验、已打开安装器/磁盘映像，但**不等于已安装**；macOS 需用户把 GoRequest 拖入“应用程序”并重新启动；不退出当前应用、不自动重启。下载完成状态会写入 `LastResult=downloaded`，设置页可追溯。
- 设置新增“更新/Updates”分类：真实运行版本、启动时自动检查开关、永远不提示开关、立即检查按钮、上次检查结果（含原始错误，便于追溯）。设置可恢复“永远不提示”和“关闭自动检查”。
- 关于页版本从写死的 `0.1.0 (MVP)` 改为实际版本：优先构建注入 `-X gorequest/internal/desktop.buildVersion=...`，否则打包版 `mygo.App.Version()`；开发/未打包运行显示“开发版本（无发布版本号）”，不参与比较。
- 沿用现有原生 `ui.Modal`、`uikit` 按钮/复选框/主题 token，没有新增原生下拉或网页视图。

### 2.4 Release 打包设置

检查了 `.github/workflows/release.yml`，现有流程已满足更新器契约，本轮**未修改**：

- 从 release tag 校验 SemVer 并写入 `mygo.json` 的 `version`，`mygo build` 通过 `-X ...packageVersion` 嵌入实际版本。
- 构建 darwin/amd64、darwin/arm64、windows/amd64、windows/arm64 四份产物，文件名含 `arm64`/`amd64` 与 `.dmg`/setup `.exe`，与 `SelectAsset` 匹配。
- `publish` 作业生成并上传 `SHA256SUMS`，更新器可回退核验。
- 当前发布没有 MyGo 签名更新 feed，因此没有调用 `mygo.Updater`（未配置时会返回 `ErrUpdatesDisabled`），也没有生成/提交任何私钥或凭据。

## 4. 限制与未验收项

- **未实机验收**：没有在真实 macOS/Windows 桌面上运行更新弹窗、下载、`open`/安装器启动或替换流程；headless 测试不能替代实机。
- **未真实联网检查**：GitHub API 的真实响应、限流头、分页 Link 行为未在本轮实际请求；测试使用固定形状的 fake JSON。主 agent 此前通过 GitHub 连接器核对过 `0.0.2-dev`/`0.0.1-dev` 与资产，但本轮没有重新请求。
- **未真实下载/安装**：校验、取消、错误路径均由 fake 覆盖；实际 dmg 挂载、Windows SmartScreen/Gatekeeper、签名与公证均未验证。当前发布无签名/公证，macOS 用户可能需手动放行。
- **Linux 无发布资产**：当前 release workflow 不构建 Linux，更新器会返回“没有适用于此平台的安装包”，不会假成功。
- **不自动完成安装**：下载并打开安装器后由用户完成；应用不退出、不自动重启。只有下一次启动报告新版本时，日常缓存才因版本变化而失效。
- **状态文件无跨进程锁**：两个应用实例同时写 `update-state.json` 时以最后写入为准；未做跨进程互斥。
- **自动检查失败也计入当日**：自动检查的网络/限流/无 Release 结果会记录为当天已检查，避免反复请求；用户取消的手动检查不计入，仍允许自动检查。手动检查始终不受此限制。
- **Release notes 为纯文本**：未用 Markdown 渲染，截断到 4000 rune，长说明在弹窗内滚动。
- **未新增菜单项**：手动检查入口在“设置 → 更新”和更新弹窗的“设置”按钮；为避免与 U21 的菜单文件冲突，未改项目菜单/基础 i18n。若集成方希望增加“检查更新…”菜单项，可在统一菜单 helper 中接线 `Manager.update.manualCheckFrom(window)`，本轮未提供该公共文件 patch。
- **版本来源依赖打包**：`mygo.IsDev()` 为真时一律视为开发版本；打包版依赖 `mygo build` 注入的 `packageVersion`。若手工 `go build` 未注入版本，则明确显示开发版本、不检查更新。
