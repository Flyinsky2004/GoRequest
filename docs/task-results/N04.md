## 2. 实际改动

### 2.1 Core 数据模型与持久化

- `internal/core/model.go`：
  - 新增 `ProtocolGraphQL = "graphql"`。
  - 新增 `GraphQLDef{Document string; OperationName string; Variables string}`；`Request.GraphQL *GraphQLDef` 使用 `yaml:"graphql,omitempty"`。
  - document 保留用户原文；variables 保留用户 JSON 文本，避免经过 float64。
- `internal/core/project.go`：
  - `newRequestWith` 增加 GraphQL 分支：`POST` + `{{baseUrl}}` + 默认合法文档 `query {\n  __typename\n}`。
  - `NewGraphQLRequest` 位于 `graphql.go`，复用同一创建路径（稳定 ID、路径、集合变量）。
- `internal/core/yaml_strict.go`：
  - `auditRequestAST` 校验 `graphql` 块必须是 mapping、只允许 `document/operationName/variables` 三个字符串标量；要求 `protocol: graphql`；拒绝 GraphQL 请求同时定义 `http.body`（单一事实来源）。
- `internal/core/yaml_preserve.go` 无需改动：通用 AST 补丁已能保留新增 `graphql` 块与多行 literal 风格；专项测试覆盖。

### 2.2 解析、operation 选择与校验

- 新增 `internal/core/graphql.go`：
  - `AnalyzeGraphQL(document, operationName)` 使用 `parser.ParseQueryWithTokenLimit`：
    - document ≤ 256 KiB；token 上限 20,000；库内 `MaxNestingDepth = 1000`。
    - 多 Operation 必须显式 `operationName`；缺失、找不到、重复名、匿名混用均报错。
    - 语法错误带 `line`/`column` 诊断。
    - Subscription 在发网前明确拒绝。
  - `ValidateGraphQL` 用于加载/保存校验：document 必填、variables 必须是 JSON object、GET 只允许 Query、method 只允许 GET/POST。
  - `parseGraphQLVariables` 使用 `json.Decoder.UseNumber()`，空输入等价 `{}`，拒绝 array/scalar/多余 JSON/超 256 KiB/超过 64 层嵌套。
  - `ResolveGraphQLVariables` 只递归解析 JSON 字符串值中的模板；数字、布尔、null、数组、嵌套对象保持原类型；敏感值注册 Redactor。
- `internal/core/validate.go`：
  - 支持 `protocol: graphql`；校验 graphql 块、method、document、variables；拒绝 `graphql` 块出现在非 graphql 协议上；拒绝 `http.body`。

### 2.3 发送计划与传输复用

- `internal/core/identity_redact.go`：
  - `BuildTrackedPlanWithOptions` 在 `AllowGraphQL` 显式开启时委派 `buildGraphQLTrackedPlan`；否则明确拒绝（Runner/diagnostics 默认拒绝）。
  - `BuildTrackedPlan` 作为单请求构建器默认允许 GraphQL。
- `internal/core/body_encode.go`：
  - `PlanOptions.AllowGraphQL` 能力开关。
  - `BuildPlanWithOptions` 对 GraphQL 明确报错，避免被当作普通 HTTP 静默发送。
- `internal/core/plan.go`：
  - `BuildPlan` 对 GraphQL 委派 tracked 路径。
- `buildGraphQLTrackedPlan`：
  - 派生 HTTP 请求（`Protocol = http`，避免递归），复用 URL/header/auth/secret 解析。
  - POST：JSON envelope `{query, operationName?, variables}`；强制 `Content-Type: application/json`，`Accept: application/graphql-response+json, application/json`。
  - GET：用 `url.Values` 写入 `query`/`operationName`/`variables`，大小写不敏感地替换 URL 与 request query 中的同名参数，避免双发 `query`。
  - 变量先独立解析并注册 secret，再合并到最终 Redactor；document 不做模板替换。
  - 传输仍走 `core.Execute`/`ExecuteWithOptions`，继承 OAuth、API Key、Cookie、代理、TLS/mTLS、target policy、重定向敏感头过滤、超时/取消、32 MiB 截断。

### 2.4 结果分类

- `ClassifyGraphQLResult`：
  - 保留 HTTP 状态、原始正文（由 `ExecResult` 持有）、`data`、`errors`、`extensions`。
  - 区分 `data` 存在/为 `null`/缺失；区分 200+errors、data+errors 部分成功、HTTP 错误、非 JSON、空正文、截断。
  - `errors[].path` 数字使用 `json.Number`，大整数不丢精度。
- 桌面结果面板用 `tab.respRedactor` 对 error message/path/extensions 做脱敏；Raw/Headers 复用既有响应视图。
